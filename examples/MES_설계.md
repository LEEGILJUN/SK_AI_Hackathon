# MES 데이터 설계 — 이동현·장영진

앞의 [`가상공장_구조.md`](가상공장_구조.md) 은 **코드가 붙기 위한 최소 형식**만
적었습니다. 이 문서는 그 위에 **무엇을 더 넣으면 좋은가**를 다룹니다.

두 가지를 구분해 주세요.

| | 성격 | 누가 정하는가 |
|---|---|---|
| 조인 키와 필수 열 | 바꾸면 코드가 깨집니다 | 고정 (아래 1장) |
| 그 외 전부 | 현실감과 시연의 설득력을 만듭니다 | **여러분 판단** |

두 번째가 이 문서의 본론입니다. 제조 현장을 아는 사람이 만든 데이터와
그렇지 않은 데이터는 시연에서 티가 납니다. 심사위원도 현장을 아는 사람일
가능성이 높습니다.

---

## 1. 고정 — 이것만 지키면 됩니다

`manifest.csv` 와 `mes.csv` 가 **`lot_id` 로 붙어야** 합니다. 그리고
`manifest.csv` 에 아래 열이 있어야 합니다.

```
image_path, line, object, date, lot_id, equipment_id, split, label, mask_path, visa_source
```

`mes.csv` 는 `lot_id` 만 맞으면 나머지 열은 자유입니다. 아래는 최소 예시일
뿐이고, **여기서 멈추지 마세요.**

```csv
lot_id,line,object,date,started_at,equipment_id,inspected_count,defect_count,operator_shift
```

확인은 `python scripts/check_factory.py` 로 합니다.

## 2. MES 데이터가 진단의 어디에 쓰이는가

무엇을 넣을지 정하려면 **어디에 쓰이는지**를 알아야 합니다. 지금 진단은
다섯 군데에서 조건을 봅니다.

| 판단 | 무엇을 묻는가 | MES 가 답해야 하는 것 |
|---|---|---|
| **커버리지 부족** | 지금 조건의 정상 패치가 뱅크에 있는가 | "지금 조건"이 무엇인가. 일자만인가, 로트·설비·교대도 조건인가 |
| **설비·광학** | 화질이 어느 시점부터 나빠졌는가 | 그 시점 전후로 무엇이 바뀌었는가 |
| **데이터 큐레이션** | 뱅크에 어떤 정상 이미지를 더 넣을 것인가 | 어떤 조건의 이미지가 부족한가 |
| **이슈 이력** | 과거에 비슷한 일이 있었는가 | 그 이슈가 어느 로트에서 났는가 |
| **스케줄러** | 야간에 쌓인 건을 아침에 보고 | 언제 생산된 것인가 |

**커버리지 부족이 특히 MES에 걸려 있습니다.** "조건"을 무엇으로 정의하느냐가
곧 그 원인의 판별 기준이 됩니다. 일자만 조건으로 두면 시나리오가 단순해지고,
설비·교대·자재 로트까지 조건으로 두면 훨씬 현실적인 케이스를 만들 수 있습니다.

## 3. 채워 주셨으면 하는 것 — 정답은 없습니다

아래는 제안이 아니라 **질문**입니다. 현장 경험에서 답이 나오는 것들이라
제가 정하면 오히려 어설퍼집니다.

### 조건 축을 몇 개로 볼 것인가

지금 예시는 라인·일자·로트·설비 넷입니다. 실제로 검출 성능에 영향을 주는
축이 더 있습니까?

- 교대조 (주간/야간) — 조명 조건이 다를 수 있음
- 자재 로트 — 원자재 배치가 바뀌면 외관이 달라짐
- 설비 정비 이력 — 정비 직후/직전
- 생산 속도 — 라인 속도가 촬영 품질에 영향
- 온습도 — 계절성

**이 중 어느 것이 실제로 미검출과 연결됩니까?** 그게 시나리오의 재료가 됩니다.
전부 넣을 필요는 없고, **하나라도 "이건 진짜 현장에서 문제가 된다"는 축이
있으면** 시연이 달라집니다.

> **축을 늘리면 진단이 자동으로 더 봅니다.** `BankProfile.conditions` 에 넣은
> 축을 진단이 전부 확인하고, **어느 축이 비었는지를 지목**합니다. 코드를
> 고칠 필요가 없습니다.
>
> ```
> shift=night 가 뱅크 v3 구성에 없음 (확인한 조건 4개 중 1개 누락)
> ```
>
> 자재 배치가 빠진 것과 야간 교대가 빠진 것은 **보충할 이미지가 다릅니다.**
> 축을 나눠 둘수록 조치가 구체적으로 나옵니다.

### 로트 크기와 생산 패턴

- 한 로트에 몇 장이 검사됩니까? 일정합니까, 들쭉날쭉합니까?
- 하루에 로트가 몇 개 돕니까?
- 주말이나 특정 시간대에 생산이 비는 패턴이 있습니까?
- 로트 전환 직후에 불량률이 튀는 현상이 있습니까?

균일한 데이터는 만들기 쉽지만 현실감이 없습니다. **불규칙성이 있어야
"이 로트만 이상하다"는 판단이 의미를 가집니다.**

### 검사 결과 기록

- `inspected_count`, `defect_count` 외에 무엇이 남습니까?
- 재검사 이력이 있습니까? (한 번 불량 판정 후 사람이 다시 보는 흐름)
- 판정 보류나 사람 확인 대기 상태가 있습니까?

### 설비 개체

작업목록에서 "특정 장비 개체만의 이상"은 이번 범위 밖으로 뒀습니다.
다만 **`equipment_id` 열은 지금 만들어 두는 게 좋습니다.** 나중에 확장할 때
데이터를 다시 만들지 않아도 됩니다.

설비가 라인당 몇 대입니까? 같은 라인에 여러 대가 병렬로 돕니까?

## 4. 시나리오와 어떻게 연결되는가

MES를 섬세하게 만들수록 **시나리오를 만들 재료가 늘어납니다.** 장영진 님과
함께 보시면 좋겠습니다.

| 시나리오 유형 | MES 에 무엇이 있으면 만들 수 있는가 |
|---|---|
| 신규 로트에서 검출률 급감 | 로트별 검사 결과. 특정 로트만 defect_count 가 0 |
| 야간 교대에서만 발생 | 교대조 열. 야간 이미지에만 화질 열화 주입 |
| 자재 배치 변경 후 발생 | 자재 로트 열. 그 배치부터 외관이 달라짐 |
| 설비 정비 후 정상화 | 정비 이력. 그 시점 전후로 화질 지표가 갈림 |
| 특정 시간대 집중 | started_at. 시간대별 분포 |

**지금 제 예시로는 첫 번째만 만들 수 있습니다.** 나머지는 MES에 그 축이
없어서 만들 수가 없습니다.

거꾸로도 성립합니다. 만들고 싶은 시나리오가 있으면 **그걸 만들 수 있게
MES를 설계**하면 됩니다. 시나리오가 먼저이고 데이터가 나중입니다.

## 5. 주의 두 가지

**사내 정보는 넣지 마세요.** 실제 공정 조건 값, 장비 공급사명, 생산 거점,
사내 결함 정의 체계는 코드·주석·문서 어디에도 들어가면 안 됩니다.
현장 경험에서 나온 **패턴**은 넣되, **식별 가능한 값**은 넣지 않습니다.

예를 들어 "로트 전환 직후 불량률이 튄다"는 패턴이고, 실제 전환 주기나
설비 모델명은 식별 정보입니다.

**시드를 고정하세요.** 불규칙성을 넣더라도 난수는 시드로 묶어야 합니다.
세 명이 각자 실행해서 같은 데이터가 나와야 재현성 목표가 성립합니다.

## 6. 정리

코드가 요구하는 것은 `lot_id` 조인과 manifest 열 10개뿐입니다. **나머지는
전부 열려 있고, 거기가 두 분의 도메인이 들어갈 자리입니다.**

제가 만든 예시는 "이 형식이면 코드가 붙는다"를 보여주는 것이지 "이 정도면
충분하다"가 아닙니다. 더 넣으실수록 시연이 좋아집니다.

무엇을 넣을지 정하시면 `python scripts/check_factory.py` 로 형식만 확인하고
진행하시면 됩니다. 열을 추가하는 것은 검사에 걸리지 않습니다.
