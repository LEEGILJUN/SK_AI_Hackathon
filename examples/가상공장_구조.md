# 가상 공장 구조 예시 — 데이터 담당용

`data/build_factory.py`, `manifest.csv`, `mes.csv` 를 만들 때의 형식 제안입니다.
그대로 쓰셔도 되고 바꾸셔도 되는데, **조인 키와 조회 함수 시그니처만은
맞춰 주세요.** 진단 에이전트가 이미 그 이름으로 읽고 있습니다.

---

## 1. VisA 실측 정보

먼저 확인해 둔 사실입니다. 설계 전제가 됩니다.

| 항목 | 값 |
|---|---|
| 아카이브 | `VisA_20220922.tar` · **1.80 GB** · CC BY 4.0 |
| 객체 | 12종 (`candle`, `capsules`, `pcb1~4`, `macaroni1~2`, `cashew`, `chewinggum`, `fryum`, `pipe_fryum`) |
| 객체당 이미지 | 정상 약 600~1000장, 결함 100장 |
| 해상도 | 1500×1000 (`capsules`, `macaroni1`), 1404×1070 (`pcb1`) |
| 결함 크기 | 원본에서 **약 40×40px**, 전체 면적의 0.1% |

원본 구조는 이렇습니다.

```
VisA_20220922/<객체>/Data/
├─ Images/Normal/    000.JPG ...
├─ Images/Anomaly/   000.JPG ...
└─ Masks/Anomaly/    000.png     ← 결함 마스크. 판정 기준 면적 계산에 씁니다
```

> **입력 해상도 주의.** 검사 파이프라인은 512로 줄여 448 중앙 크롭을 씁니다.
> 흔히 쓰는 256/224로는 결함이 격자 한 칸에 묻혀 AUROC 0.53(무작위 수준)이
> 나왔습니다. 448에서 0.998입니다. 데이터를 미리 축소해서 저장하지 마세요.

## 2. 폴더트리

VisA 객체 3~4개를 각각 별개 라인으로 봅니다.

```
data/factory/                         ← .gitignore 됨. 스크립트로 재현
├─ line_01/                           (candle)
├─ line_02/                           (capsules)
│  ├─ 2026-06-01/
│  │  ├─ LOT-20260601-001/
│  │  │  ├─ img_0001.png
│  │  │  └─ img_0002.png
│  │  └─ LOT-20260601-002/
│  ├─ 2026-06-02/
│  ...
│  └─ 2026-06-07/
└─ line_03/                           (pcb1)
```

일자 배분은 기획서대로입니다.

| 일자 | 용도 |
|---|---|
| 06-01 ~ 06-04 | 초기 뱅크 구성 + **화질 기준 분포 산출** |
| 06-05 ~ 06-07 | 운영 데이터. 시나리오별 조작이 들어감 |

> 화질 기준 분포는 **반드시 1~4일분에서만** 뽑아야 합니다. 열화를 주입한
> 5~7일분이 섞이면 기준 자체가 오염되어 설비·광학 원인을 영영 못 잡습니다.

## 3. manifest.csv — 이미지와 조건을 잇는 표

진단이 "이 로트의 이미지 전부"를 뽑을 수 있어야 합니다. 조인 키가 핵심입니다.

```csv
image_path,line,object,date,lot_id,equipment_id,split,label,mask_path,visa_source
line_02/2026-06-01/LOT-20260601-001/img_0001.png,line_02,capsules,2026-06-01,LOT-20260601-001,EQ-02-A,bank,normal,,capsules/Data/Images/Normal/000.JPG
line_02/2026-06-05/LOT-20260605-014/img_0142.png,line_02,capsules,2026-06-05,LOT-20260605-014,EQ-02-A,operation,defect,line_02/.../img_0142_mask.png,capsules/Data/Images/Anomaly/003.JPG
```

| 열 | 설명 |
|---|---|
| `image_path` | `data/factory/` 기준 상대 경로. 뱅크가 이 문자열로 출처를 기록합니다 |
| `line`, `object` | 조회 함수의 첫 두 인자와 같은 값이어야 합니다 |
| `date`, `lot_id`, `equipment_id` | 커버리지 판정의 조건 키 |
| `split` | `bank` / `operation` / `holdout` |
| `label` | `normal` / `defect` |
| `mask_path` | 결함일 때만. 판정 기준 면적 계산용 |
| `visa_source` | 어느 원본에서 왔는지. 재현과 추적용 |

`equipment_id` 는 지금 범위에서 쓰지 않지만 열은 만들어 두시죠. 나중에
"특정 장비 개체만의 이상"으로 확장할 때 데이터를 다시 만들지 않아도 됩니다.

## 5. 조회 계층 — 여기가 접합부입니다

`lookup/base.py` 에 함수 8개가 정의돼 있습니다. 이것만 구현하면
`lookup/mock.py` 를 빼고 끼울 수 있고, **진단 코드는 한 줄도 안 바뀝니다.**

```python
# 판별 항목용 — 3·2·7·6번과 중복 차단
get_threshold(line, object_name, bank_version)    -> ThresholdRecord | None
get_quality_baseline(line, object_name)           -> QualityBaselineRecord | None
get_criteria(line, object_name, defect_type, at)  -> CriteriaRule | None
get_bank_profile(bank_version)                    -> BankProfile | None
find_similar_issues(line, object_name, defect_type, limit) -> list[PastIssue]

# MES 쪽 — 판별 항목 앞 단계
resolve_bank(line, object_name)                   -> BankProfile | None
find_images(line, object_name, lot, product_id, limit) -> list[ImageRecord]
defect_distribution(line, object_name, defect_type, since) -> DefectDistribution
```

앞의 다섯은 판별 항목 3·2·7·6번과 중복 차단에 대응합니다.

**뒤의 셋은 그 앞 단계입니다.** 접수된 이슈는 이미지가 아니라 제품명이나
로트로 옵니다("A-217 로트가 계속 빠집니다"). 그것을 이미지로 바꾸고 그 품목의
뱅크를 찾아야 비로소 판별 항목을 잴 수 있습니다.

**뱅크는 품목마다 따로입니다.** 캡슐 정상 패치로 PCB 를 판정할 수 없어서
`resolve_bank` 가 필요합니다. 없는 품목이면 `None` 이고, 그것이 "아직 배포된
모델이 없다"는 답입니다.

**셋 다 조인으로 답하세요. 임베딩하지 마세요.** "3라인 A-217 로트 캡슐 이미지
목록"은 정확히 답할 문제고, 벡터 검색을 쓰면 비슷한 로트를 섞어 옵니다.

`find_images` 는 없으면 **빈 목록**, `defect_distribution` 은 없으면
**`total=0` 인 빈 집계**입니다(`None` 아님). "몰린 곳이 없다"와 "못 셌다"를
부르는 쪽이 구분할 수 있어야 하기 때문입니다.

두 가지만 지켜 주세요.

**값을 못 찾으면 예외가 아니라 `None`.** 진단은 "근거를 얻지 못했다"를 하나의
상태로 다룹니다. 조회 실패로 멈추면 안 됩니다.

**`get_criteria` 의 `at` 은 그 시점에 유효했던 기준을 돌려줍니다.** 기준을
덮어쓰지 말고 쌓으세요. 과거 이슈를 지금 기준으로 판정하면 "기준 문제"
시나리오를 영영 찾지 못합니다.

`BankProfile.conditions` 는 이런 모양이면 됩니다.

```python
{"date": ["2026-06-01", ..., "2026-06-04"],
 "lot":  ["LOT-20260601-001", ...],
 "equipment": ["EQ-02-A"]}
```

진단은 `profile.covers("date", "2026-06-20")` 처럼 물어봅니다. 이게 `False` 면
커버리지 부족으로 갑니다.

## 6. 학습 이력 인덱서가 읽을 것

뱅크를 만들면 `bank_meta.json` 이 함께 저장됩니다. 인덱서(작업 10)는 이걸
스캔하면 됩니다. 별도 형식을 새로 정의하지 않으셔도 됩니다.

```json
{
  "bank_version": "v3",
  "grid": [56, 56],
  "source_image_count": 113,
  "patch_count": 3544,
  "coreset_ratio": 0.01,
  "coreset_capped": false,
  "seed": 42,
  "feature_config": {"backbone": "wide_resnet50_2", "resize": 512, "crop": 448},
  "images": ["line_02/2026-06-01/LOT-20260601-001/img_0001.png", "..."]
}
```

`images` 가 뱅크 구성 이력 그 자체입니다. 이것만 있으면 "이 뱅크에 어느
조건이 들어갔는가"를 manifest 와 조인해서 복원할 수 있습니다.

역추정한 이력은 `BankProfile.is_estimated=True` 로 표시해 주세요. 담당자
확인 전에는 추정으로 남는다는 원칙이 있습니다.

## 7. 재현성

시드를 고정해 각자 실행하면 같은 트리가 나와야 합니다. "데이터를 공유했다"가
아니라 "누구나 같은 데이터를 만들 수 있다"가 되어야 재현성 100% 목표가
성립합니다.

```bash
python data/build_factory.py --visa-root VisA_20220922 --seed 20260601
```

`VisA_20220922/` 와 `data/factory/` 는 둘 다 `.gitignore` 에 있습니다.
**절대 커밋하지 마세요.** 저장소 루트에 압축을 풀면 1.8GB가 커밋 대상으로
잡힙니다(실제로 한 번 걸렸습니다).

## 8. 시나리오 조작을 어디서 하는가

`data/scenarios.yaml` 의 `injection` 블록을 `build_factory.py` 가 읽어 데이터를
만드는 구조가 깔끔합니다. 정답과 데이터가 한곳에서 나오므로 어긋날 일이
없습니다.

| method | 무엇을 하는가 |
|---|---|
| `bank_contamination` | 결함 이미지 N장을 정상 학습셋에 섞음 |
| `coverage_exclude` | 특정 일자·로트의 정상 이미지를 뱅크 구성에서 제외 |
| `image_degrade` | 지정 일자 이후 이미지에 블러·밝기 시프트 적용 |
| `threshold_shift` | 임계값을 실제 결함 점수 분포보다 높게 설정 |
| `criteria_change` | 마스크 면적 기준 임계값을 도중에 변경 |
| `overlap_select` | 조작 없음. 정상과 가까운 결함 유형을 고르기만 함 |
| `none` | 조작 없음 |

`overlap_select` 만 성격이 다릅니다. 데이터를 건드리지 않고 **선정**만 하며,
고른 뒤 점수 분포가 실제로 겹치는지 확인이 필요합니다.
