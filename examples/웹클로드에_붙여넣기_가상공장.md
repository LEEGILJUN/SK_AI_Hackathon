====================== 여기부터 복사 ======================

당신은 제조 AI 외관검사 시스템의 데이터 계층을 만드는 일을 돕습니다.
저는 가상 공장 스토리지, MES 데이터, 학습 이력 인덱서, 조회 계층을
담당합니다. Python 을 씁니다.

## 배경

이미 배포된 AI 외관검사 모델(PatchCore)이 불량을 못 잡았을 때 에이전트가
원인을 진단합니다. 진단은 7가지 판별 항목을 조합하는데, 그중 4개가 제가
만드는 조회 계층에서 나옵니다. 진단 로직과 추론 파이프라인은 **이미 구현되어
있고**, 지금은 목(mock) 데이터를 보고 있습니다. 제가 실제 구현을 만들면
목을 빼고 끼웁니다.

**중요**: 인터페이스는 이미 고정돼 있습니다. 아래 시그니처를 그대로 지켜야
진단 코드를 고치지 않고 붙습니다.

데이터는 VisA 공개 데이터셋을 씁니다. 사내 데이터는 일절 쓰지 않으므로
실제 공정 조건, 장비 공급사명, 생산 거점은 절대 넣지 마세요. 전부 가상값입니다.

## VisA 실측 정보

| 항목 | 값 |
|---|---|
| 아카이브 | `VisA_20220922.tar` · 1.80 GB · CC BY 4.0 |
| 객체 | 12종 (candle, capsules, pcb1~4, macaroni1~2, cashew, chewinggum, fryum, pipe_fryum) |
| 객체당 | 정상 600~1000장, 결함 100장 |
| 해상도 | 1500x1000 (capsules, macaroni1), 1404x1070 (pcb1) |
| 결함 크기 | 원본에서 약 40x40px, 전체 면적의 0.1% |

원본 구조:

```
VisA_20220922/<객체>/Data/
├─ Images/Normal/    000.JPG ...
├─ Images/Anomaly/   000.JPG ...
└─ Masks/Anomaly/    000.png      ← 결함 마스크. 판정 기준 면적 계산용
```

**이미지를 미리 축소해서 저장하지 마세요.** 검사 파이프라인이 512로 줄여
448 중앙 크롭을 씁니다. 256/224로는 결함이 격자 한 칸에 묻혀 AUROC 0.53
(무작위 수준)이 나옵니다. 448에서 0.998입니다.

## 만들어야 할 것 1 — 가상 공장 폴더트리

VisA 객체 3~4개를 각각 별개 라인으로 봅니다.

```
data/factory/
├─ line_01/                    (candle)
├─ line_02/                    (capsules)
│  ├─ 2026-06-01/
│  │  ├─ LOT-20260601-001/
│  │  │  ├─ img_0001.png
│  │  │  └─ img_0002.png
│  │  └─ LOT-20260601-002/
│  └─ ... 2026-06-07/
└─ line_03/                    (pcb1)
```

| 일자 | 용도 |
|---|---|
| 06-01 ~ 06-04 | 초기 뱅크 구성 + 화질 기준 분포 산출 |
| 06-05 ~ 06-07 | 운영 데이터. 시나리오별 조작이 들어감 |

**시드를 고정**해야 합니다. 세 명이 각자 실행해서 같은 트리가 나와야
재현성 목표(동일 입력 10회 반복 시 동일 판정 100%)가 성립합니다.

화질 기준 분포는 **반드시 1~4일분에서만** 산출해야 합니다. 열화를 주입한
5~7일분이 섞이면 기준 자체가 오염되어 설비·광학 원인을 영영 못 잡습니다.

## 만들어야 할 것 2 — manifest.csv 와 mes.csv

```csv
# manifest.csv — 이미지와 조건을 잇는다
image_path,line,object,date,lot_id,equipment_id,split,label,mask_path,visa_source
line_02/2026-06-01/LOT-20260601-001/img_0001.png,line_02,capsules,2026-06-01,LOT-20260601-001,EQ-02-A,bank,normal,,capsules/Data/Images/Normal/000.JPG
```

- `image_path` — `data/factory/` 기준 상대 경로. 뱅크가 이 문자열로 출처를 기록합니다
- `split` — `bank` / `operation` / `holdout`
- `label` — `normal` / `defect`
- `mask_path` — 결함일 때만

```csv
# mes.csv — 로트 단위 생산 기록
lot_id,line,object,date,started_at,equipment_id,inspected_count,defect_count,operator_shift
LOT-20260601-001,line_02,capsules,2026-06-01,2026-06-01T08:00:00,EQ-02-A,120,2,day
```

`lot_id` 로 두 파일이 붙습니다. **벡터화하지 않습니다** — 조인과 집계로
정확히 답할 문제이며, 임베딩하면 오히려 정확도가 떨어집니다.

## 만들어야 할 것 3 — 조회 계층 (여기가 접합부)

아래 자료형과 함수 5개를 구현하면 됩니다. **이름과 시그니처를 바꾸지 마세요.**
저장소는 표준 라이브러리 `sqlite3` 면 충분합니다.

```python
from dataclasses import dataclass, field
from datetime import date
from typing import Any

@dataclass
class ThresholdRecord:          # 판별 3번
    line: str
    object_name: str
    bank_version: str
    value: float
    effective_from: date | None = None
    note: str = ""

@dataclass
class QualityBaselineRecord:    # 판별 2번
    line: str
    object_name: str
    stats: dict[str, dict[str, float]]   # {"brightness": {"mean":.., "std":..}, ...}
    computed_from: dict[str, Any] = field(default_factory=dict)
    tolerance_sigma: float = 3.0
    outlier_ratio_threshold: float = 0.30

@dataclass
class CriteriaRule:             # 판별 7번
    rule_id: str
    line: str
    object_name: str
    defect_type: str | None
    defect_area: float          # 이 면적 이상이면 불량
    review_area: float | None = None
    effective_from: date | None = None
    effective_to: date | None = None

@dataclass
class BankProfile:              # 판별 6번
    bank_version: str
    line: str
    object_name: str
    source_image_count: int
    patch_count: int
    conditions: dict[str, list[str]] = field(default_factory=dict)
    built_at: date | None = None
    is_estimated: bool = False   # 폴더 스캔으로 역추정한 이력인가

@dataclass
class PastIssue:                # 그래프 검색 (중복 차단 전용)
    issue_id: str
    line: str
    object_name: str
    cause: str
    action: str
    resolved: bool
    similarity: float
    summary: str = ""
```

구현할 함수:

```python
class MyLookup:
    def get_threshold(self, line: str, object_name: str,
                      bank_version: str) -> ThresholdRecord | None: ...

    def get_quality_baseline(self, line: str,
                             object_name: str) -> QualityBaselineRecord | None: ...

    def get_criteria(self, line: str, object_name: str,
                     defect_type: str | None = None,
                     at: date | None = None) -> CriteriaRule | None: ...

    def get_bank_profile(self, bank_version: str) -> BankProfile | None: ...

    def find_similar_issues(self, line: str, object_name: str,
                            defect_type: str | None = None,
                            limit: int = 5) -> list[PastIssue]: ...
```

지켜야 할 규칙 세 가지:

1. **값을 못 찾으면 예외가 아니라 `None`** 을 돌려주세요. 진단은 "근거를
   얻지 못했다"를 하나의 상태로 다룹니다. 조회 실패로 멈추면 안 됩니다.

2. **`get_criteria` 의 `at` 은 그 시점에 유효했던 기준**을 돌려줍니다.
   기준을 덮어쓰지 말고 쌓으세요. 과거 이슈를 지금 기준으로 판정하면
   "기준 문제" 시나리오를 영영 찾지 못합니다.

3. **`BankProfile.conditions`** 는 이런 모양입니다.
   ```python
   {"date": ["2026-06-01", ..., "2026-06-04"],
    "lot":  ["LOT-20260601-001", ...],
    "equipment": ["EQ-02-A"]}
   ```
   진단이 `profile.covers("date", "2026-06-20")` 처럼 묻습니다.
   `False` 면 커버리지 부족으로 갑니다.

## 만들어야 할 것 4 — 학습 이력 인덱서

뱅크를 만들면 `bank_meta.json` 이 함께 저장됩니다. 이걸 스캔하면 됩니다.
**새 형식을 정의하지 않으셔도 됩니다.**

```json
{
  "bank_version": "v3",
  "grid": [56, 56],
  "source_image_count": 113,
  "patch_count": 3544,
  "coreset_ratio": 0.01,
  "seed": 42,
  "feature_config": {"backbone": "wide_resnet50_2", "resize": 512, "crop": 448},
  "images": ["line_02/2026-06-01/LOT-20260601-001/img_0001.png", "..."]
}
```

`images` 가 뱅크 구성 이력 그 자체입니다. manifest 와 조인하면 "이 뱅크에
어느 조건이 들어갔는가"가 복원됩니다.

**사내 폴더 구조를 전제하지 마세요.** 일반적인 스캔 규칙으로 짜야 합니다.
역추정한 이력은 `is_estimated=True` 로 표시하고, 담당자 확인 후에만 확정으로
승격합니다.

## 시나리오 조작

`data/scenarios.yaml` 의 `injection` 블록을 `build_factory.py` 가 읽어
데이터를 만드는 구조를 씁니다. 정답과 데이터가 한곳에서 나오므로 어긋나지
않습니다.

| method | 무엇을 하는가 |
|---|---|
| `bank_contamination` | 결함 이미지 N장을 정상 학습셋에 섞음 |
| `coverage_exclude` | 특정 일자·로트의 정상 이미지를 뱅크 구성에서 제외 |
| `image_degrade` | 지정 일자 이후 이미지에 블러·밝기 시프트 적용 |
| `threshold_shift` | 임계값을 실제 결함 점수 분포보다 높게 설정 |
| `criteria_change` | 마스크 면적 기준 임계값을 도중에 변경 |
| `overlap_select` | 조작 없음. 정상과 가까운 결함 유형을 고르기만 함 |
| `none` | 조작 없음 |
