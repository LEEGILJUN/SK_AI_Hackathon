# 문서 지도 — 무엇을 언제 고치는가

문서는 조용히 낡습니다. 코드를 바꿔도 문서는 그대로 남고, 아무도 눈치채지
못한 채 팀원이 그 문서를 보고 엉뚱한 일을 합니다. 실제로 이 저장소에서도
폴더 이름을 바꾼 뒤 세 곳이 낡은 채로 있었고, 테스트 건수가 89로 적힌 곳이
있었습니다(실제 146).

그래서 두 가지를 둡니다. **어떤 변경이 어떤 문서를 낡게 하는지 적은 표**와,
**기계가 매번 확인하는 검사기**입니다.

```bash
.venv/bin/python scripts/check_docs.py
```

## 2. 이걸 바꾸면 저걸 고쳐야 합니다

가장 자주 어긋나는 것들입니다. 왼쪽 일을 했으면 오른쪽을 확인하세요.

| 무엇을 바꿨나 | 고쳐야 할 문서 |
|---|---|
| 패키지·폴더를 추가하거나 이름을 바꿈 | `CLAUDE.md` 패키지 지도 · `docs/작업목록.md` 7장 구조 · `docs/깃사용법.md` 폴더트리 |
| 작업을 끝냄 | `README.md` 체크리스트 (**남의 몫까지 체크하지 말 것**) · `CLAUDE.md` 구현 현황 |
| `lookup/base.py` 인터페이스 변경 | `examples/가상공장_구조.md` · `examples/웹클로드에_붙여넣기_가상공장.md` · `tests/test_lookup_contract.py` |
| `data/scenarios.yaml` 스키마 변경 | `examples/scenarios_예시.yaml` · `examples/웹클로드에_붙여넣기_시나리오.md` · `scripts/check_scenarios.py` |
| 측정으로 설정값이 바뀜 (해상도 등) | `CLAUDE.md` 실측값 절 · `docs/이어서작업.md` 4장 · 해당 코드 docstring |
| 라이브러리 추가 | `requirements.txt` · `THIRD_PARTY.md` |
| 새 스크립트 추가 | `CLAUDE.md` 확인 명령 · `README.md` (팀원이 쓸 것이면) |
| 새 문서 추가 | **이 문서의 1장 목록** (안 하면 `check_docs.py` 가 잡습니다) |

## 3. 낡기 쉬운 값

문서에 숫자를 박으면 낡습니다. 아래는 특히 잘 어긋나는 것들입니다.

| 값 | 어디에 있나 | 어떻게 확인하나 |
|---|---|---|
| 테스트 건수 | `CLAUDE.md`, `docs/이어서작업.md` | `check_docs.py` 가 실제와 대조합니다 |
| 파일 경로 | 문서 전반 | `check_docs.py` 가 존재 여부를 봅니다 |
| 옛 폴더 이름 (`inspect/`) | 문서 전반 | `check_docs.py` 가 잡습니다 |
| 커밋 해시 | 문서에 쓰지 마세요 | — |
| 측정값 (AUROC 등) | `CLAUDE.md`, `docs/이어서작업.md` | **기계가 못 잡습니다.** 재측정하면 손으로 고쳐야 합니다 |
| **모델 이름** | `CLAUDE.md`, `docs/이어서작업.md`, `docs/모델선정과_VRAM.md` | **기계가 못 잡습니다.** 설정과 측정 기록을 구분하세요 — 아래 |

**모델 이름은 두 가지 뜻으로 쓰입니다.** `docs/실험_*.md` 와
`scripts/measure_*.py` 의 모델명은 **그때 무엇으로 쟀는지**를 적은 것이라
고치면 안 됩니다. `CLAUDE.md` 와 `docs/이어서작업.md` 의 모델명은 **지금 쓰는
설정**이라 바뀌면 고쳐야 합니다. 실제로 이 둘을 섞어 읽어 이미 `gemma4-12b-vision`
으로 정해진 것을 `qwen` 으로 착각한 적이 있습니다.

측정값도 같습니다. **자동 검사가 안 됩니다.** 해상도를 바꾸거나
데이터가 바뀌어 다시 재면, 문서의 표도 함께 고쳐야 합니다. 안 고치면 다음
사람이 옛 수치를 근거로 판단합니다.

## 4. 검사기가 보는 것과 못 보는 것

```bash
.venv/bin/python scripts/check_docs.py
```

**봅니다**

1. 문서가 가리키는 경로가 실제로 있는가
2. 문서에 박힌 테스트 건수가 실제와 맞는가
3. 이름이 바뀐 것을 옛 이름으로 부르고 있지 않은가
4. 새로 생긴 문서가 이 지도에 등록됐는가

**못 봅니다**

- 내용이 맞는지 (설명이 코드가 실제로 하는 일과 같은지)
- 측정값이 최신인지
- 설계 의도가 바뀌었는데 문서가 옛 의도를 설명하는지

아직 만들지 않은 파일을 문서가 가리키는 것은 정상입니다
(`data/build_factory.py` 처럼 팀원이 앞으로 만들 것). `check_docs.py` 의
`PLANNED` 목록에 있으면 넘어갑니다. 새로 그런 파일이 생기면 거기 추가하세요.

## 5. 언제 돌리나

- 문서를 고친 뒤
- 폴더 구조나 인터페이스를 바꾼 뒤
- 다른 사람에게 저장소를 넘기기 전
- 제출 전

`scripts/check_scenarios.py`(시나리오 형식)와 `scripts/check_factory.py`
(가상 공장 데이터)도 같은 성격입니다. 셋 다 **"맞았는지 사람이 판단하지
않아도 되게"** 만든 것입니다.
