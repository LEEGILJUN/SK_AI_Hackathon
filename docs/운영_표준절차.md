# 운영 표준 절차 — 현업에서 이 서비스를 어떻게 쓰는가 (작업 23)

**사람이 무엇을 하고 무엇을 안 하는가**를 정합니다. 자동화의 값어치는 사람이
빠진 자리에서 나오는 것이 아니라, **사람이 남아야 할 자리가 어디인지 정해질
때** 나옵니다.

이 문서는 지금 코드가 실제로 하는 것을 기준으로 씁니다. 아직 안 된 것은
그렇다고 적습니다.

---

## 1. 전체 흐름 — 사람은 네 곳에 있습니다

```
       [자동]                                   [사람]
이슈 접수 ──────────────────────────────────▶ ① 정보가 모자라면 되묻는 답
   │
   ├─ 인테이크    정보 충분한가 · 중복인가
   ├─ MES 조회    제품명·로트로 이미지를 찾는다
   ├─ 추론        그 품목 뱅크로 미검·과검을 가른다
   ├─ 판별 7항목  ──────────────────────────▶ ② 판별 1·5번이 보류면 사람 판독
   ├─ 진단        원인 6종 중 하나 (근거 필수)
   │
   │  ┌── 재구성이 답이 아닌 원인 넷 → 여기서 멈춘다
   │  └── 뱅크 오염 · 커버리지 부족만 아래로
   │
   ├─ 큐레이션    무엇을 빼고 무엇을 넣을 것인가
   ├─ 재구성      후보 뱅크를 만든다 (배포 아님)
   ├─ 게이트      통과 기준 대조
   ├─ 섀도        신·구 뱅크가 갈린 건만 추출 ─▶ ③ 갈린 건만 사람이 확인
   └─ 승인 요청   문서와 배포 패키지 생성
                                            ──▶ ④ 승인하고 전환 명령 실행
```

**사람이 있는 네 곳이 전부 "판단"입니다.** 실행이나 확인 작업이 아닙니다.

---

## 2. 사람이 하는 일 넷

### ① 인테이크가 되물었을 때 답한다

정보가 모자라면 **추측하지 않고 되묻습니다.** 라인·품목·제품명 칸은 그때만
열립니다.

미리 띄워 두지 않는 이유가 있습니다. 칸이 있으면 사람이 그것부터 채우게
되고, 그러면 언어 모델이 이슈 원문에서 뽑을 일이 없어져 자연어 입력이
장식이 됩니다.

> **접수할 때 쓰는 말** — 평소 쓰는 문장 그대로 씁니다. 정해진 양식이
> 없습니다. 제품명이나 로트를 알면 함께 적으시고, 모르면 안 적어도 됩니다.

### ② 판별 1·5번이 보류되면 사람이 판독한다

일곱 판별 중 **둘만 시각 판독**이고 나머지는 조회와 계산입니다. 그 둘이
보류되는 경우가 있습니다.

| | 무엇을 보나 | 보류되면 |
|---|---|---|
| 판별 1번 | 접수된 이미지에 결함이 보이는가 | **진단이 멈춥니다** |
| 판별 5번 | 뱅크의 그 패치가 잘못 들어간 결함인가 | 뱅크 오염과 정상 분포 중첩을 못 가릅니다 |

**판별 1번이 멈추는 것은 고장이 아닙니다.** 결함이 안 보이면 미검출이 아니라
접수 오류이거나 다른 이미지가 첨부됐을 수 있고, 그 상태에서 원인을 정하면
엉뚱한 이미지로 뱅크를 고치게 됩니다.

> **현재 한계** — 기판에서 결함 위치를 짚는 정확도가 상위 1자리 3/10 입니다.
> 정확한 위치를 주면 판독이 80.8%(12품목) 이므로 **모델이 아니라 위치 추정의 문제**
> 입니다. 그래서 판별 1번이 실제보다 자주 보류될 수 있습니다. 화면이 잘라
> 보여주는 자리를 사람이 보고 판단하시면 됩니다.

### ③ 섀도에서 갈린 건만 확인한다

새 뱅크를 실제 판정에 쓰지 않고 **같은 이미지에 병렬로만** 돌려, 신·구 판정이
갈린 건만 뽑습니다.

```
14장을 두 뱅크로 각각 추론 → 갈린 것 1장
사람이 볼 것은 그 1장뿐
```

양산 데이터에는 정답이 없고, 새 뱅크를 배포해 버리면 옛 뱅크는 더 이상
동작하지 않아 같은 조건 비교가 불가능합니다. 섀도는 그것을 피하면서 정답도
확보합니다 — **사람이 확인한 그 한 장이 정답 라벨이 됩니다.**

### ④ 승인하고 전환 명령을 실행한다

승인 요청 문서에 **전환 명령이 실제 폴더 이름으로** 찍혀 있습니다. 복사해서
실행하시면 됩니다.

```
python scripts/switch_bank.py --item pcb1-01 --to pcb1-01-v2_20260816-0910_cad872 \
    --by 에이전트 담당 --reason "ISS-0051 뱅크 오염. 게이트 4항목 통과, 섀도 1건 갈림"
```

**이것을 자동화하지 않습니다.** 품질 검사 설비에 사람 확인 없이 새 모델이
들어가는 것을 의도적으로 배제했고, 그 경계를 코드가 지킵니다 — 에이전트와
스케줄러에서 전환 함수를 부르면 시험이 실패합니다.

승인 전에 볼 것 셋입니다.

| 무엇 | 어디에 | 무엇을 보나 |
|---|---|---|
| 진단 근거 | `diagnosis.json` · 승인요청.md | 판별 7항목의 값. 보류된 항목이 있는가 |
| 게이트 | `gate.json` | 어느 항목이 어느 기준으로 통과했는가 |
| 결함 분포 | 승인요청.md | 특정 로트·설비에 몰려 있지 않은가 |

**결함이 한 로트에 몰려 있으면 뱅크를 고치기 전에 그쪽을 먼저 봐야 합니다.**
자재나 설비 문제일 수 있고, 그때 뱅크를 다시 만들면 원인은 그대로 두고
증상만 덮는 것입니다. 승인 문서가 그 집계를 함께 적습니다.

## 3. 되돌리기

새 뱅크를 쓰기 시작한 뒤 문제가 보이면 **한 줄로 되돌립니다.**

```
python scripts/switch_bank.py --item pcb1-01            어떤 판이 있나
python scripts/switch_bank.py --item pcb1-01 --to <이전 판 이름> --by <이름> --reason <근거>
```

파일은 움직이지 않습니다. 가리키는 이름만 바뀌므로 **되돌린 뒤에도 새 판이
남아 다시 앞으로 갈 수 있습니다.**

**되돌린 이유는 자동으로 남습니다.** `--by` 와 `--reason` 이 필수라 안 적으면
전환이 거부되고, 판 번호가 낮아지면 되돌리기로 표시됩니다.

```
python scripts/switch_bank.py --item pcb1-01 --history
```

**같은 품목을 자주 되돌린다면 게이트 기준이 느슨하다는 신호입니다.** 두 번
이상이면 화면이 그렇게 적습니다.

## 4. 자동으로 도는 것 — 야간 점검

이슈가 접수되지 않아도 **지정 시각에 스스로** 밤새 쌓인 생산분을 점검합니다.

미검 의심 건을 찾으면 **사람이 접수한 것과 똑같은 경로로** 이슈를 만들어
넣습니다. 전용 진단 경로를 따로 두지 않은 것이 설계입니다 — 두 벌이 되면
한쪽만 고쳐져 시연과 실제가 갈립니다.

**한 번에 다섯 건까지만 처리하고 남은 건수를 보고서에 적습니다.** 섀도의
논거가 "불일치 건만 보면 되니 공수가 준다"인데, 아침에 수백 건을 들이밀면
그 논거가 무너집니다.

아침에 받는 것은 **승인 요청 문서 몇 건**이고, 하는 일은 위 ④ 와 같습니다.

---

## 5. 진단이 멈추는 경우와 그때 할 일

멈추는 것은 실패가 아닙니다. **근거가 모자라면 판정하지 않는다**가 설계이고,
찍으면 절반은 정반대 조치를 지시하게 됩니다.

| 멈춘 지점 | 무엇이 모자란가 | 할 일 |
|---|---|---|
| 인테이크 | 라인·품목·제품명 | 되물음에 답한다 |
| 인테이크 | — (중복으로 끊김) | 과거 건을 확인한다. 라인이 다르면 중복이 아니므로 다시 접수 |
| MES 조회 | 그 품목에 배포된 뱅크가 없음 | 초기 뱅크를 먼저 구성한다 |
| 판별 1번 | 결함이 안 보임 | 이미지를 직접 확인. 다른 이미지면 재접수 |
| 판별 5번 | 패치가 결함인지 정상품인지 불명 | 화면의 크롭을 보고 판단해 지정 |
| 진단 | 역추적 실패 | 뱅크와 추론 설정이 맞는지 확인 |
| 큐레이션 | 뺄 것도 넣을 것도 없음 | 원인이 재구성으로 풀리지 않는 것. 조치는 진단이 제시 |
| 게이트 | 기준 미달 | 후보를 쓰지 않는다. 미달 항목이 무엇인지가 다음 조치를 정함 |

**재구성이 답이 아닌 원인 넷**(임계값 문제 · 정상 분포 중첩 · 설비·광학 ·
기준 문제)에서는 뱅크를 건드리지 않고 멈추는 것이 정상 동작입니다. 그때
제시되는 조치는 임계값 재조정 · 기준 재정의 · 설비 점검이며, **전부 사람이
하는 일**입니다.

---

## 6. 이 절차가 전제하는 것

지금 코드가 실제로 지키는 것들입니다. 하나라도 깨지면 절차가 성립하지
않습니다.

- **뱅크는 라인·품목마다 따로입니다.** 캡슐 정상 패치로 기판을 판정할 수
  없습니다. 실측에서 같은 보드의 앞뒤면조차 완전히 갈렸습니다
- **다른 라인의 같은 증상은 중복이 아닙니다.** 1라인이 오염됐다고 2라인도
  그렇다는 뜻이 아닙니다
- **판정은 규칙이 하고 언어 모델은 서술만 합니다.** 모델은 어떤 도구를 어떤
  순서로 부를지를 정하고, 원인은 판별 7항목이 냅니다
- **배포 함수가 없습니다.** 코드에 그런 이름의 함수가 생기면 시험이 실패합니다

---

## 7. 아직 안 정해진 것

절차를 현업에 붙이기 전에 사람이 정해야 하는 값들입니다.

| 무엇 | 지금 | 누가 정하나 |
|---|---|---|
| 게이트 통과 기준 | `data/gate.yaml` 에 기본값과 근거. 라인별로 덮어쓸 수 있음 | 품질 담당 |
| 판정 기준 면적 임계값 | `data/criteria.yaml`. **면적 계산 방식을 바꿔 값이 미확정** | 품질 담당 |
| 화질 기준 분포 | 라인별 베이스라인 | 설비 담당 |
| 야간 점검 시각과 처리 건수 | 시각은 설정, 건수는 5건 | 운영 담당 |
| 승인 권한 | 정해지지 않음 | 조직이 정할 일 |

**마지막 줄이 가장 중요합니다.** 누가 승인할 수 있는가가 정해지지 않으면
④ 가 성립하지 않습니다. 기록을 남기는 자리는 만들어 뒀습니다 — `--by` 에
적힌 이름이 그것이고, 그 이름이 승인 권한을 가진 사람인지는 조직이 정합니다.
