# 검사 AI 자율 운영 에이전트 — 설명서

**Self-Healing Vision Ops** · 2026 SK AI 해커톤 AI Solution 리그

이 문서는 **처음 보는 사람**을 위한 것입니다. 무엇을 만들었고, 어떻게
동작하며, 어떻게 실행하는지를 적습니다. 설득하려는 문서가 아니라 설명하는
문서이므로 **안 되는 것도 함께 적습니다.**

---

## 1. 무엇을 만들었나

제조 현장에 배포된 AI 외관검사 모델이 **"못 잡는 불량"** 을 만났을 때,
원인 진단부터 데이터 선별, 메모리 뱅크 재구성, 성능 검증, 배포 패키지
생성까지를 에이전트가 스스로 수행합니다.

**검사 모델을 만드는 것이 아닙니다.** 이미 배포된 모델을 계속 살아 있게
유지하는 **운영의 문제**를 다룹니다. 모델은 배포하는 순간부터 낡기 시작하고,
그것을 되살리는 일은 지금 사람 손에 남아 있습니다.

### 왜 진단이 가능한가

기준 모델은 **PatchCore** 입니다. 정상 이미지의 패치를 메모리 뱅크에 담아
두고 **가장 가까운 정상 패치와의 거리**로 이상 여부를 판정합니다.

이 구조 때문에 미검출이 발생했을 때 **그 이미지가 뱅크의 어떤 정상 패치와
가까웠는지를 되짚을 수 있습니다.** 판단 근거가 모델 안에 이미 존재하므로,
진단이 추측이 아니라 **추적**이 됩니다.

## 2. 어떻게 동작하나 — 열 단계

```
이슈 접수 → 인테이크 → MES 조회 → 추론 → 판별 7항목 → 진단
         → 큐레이션 → 재구성 → 게이트 → 섀도 → 승인 요청
```

| # | 단계 | 무엇을 하는가 |
|---|---|---|
| 1 | 인테이크 | 자연어 이슈에서 라인·품목·제품명을 뽑고, 정보가 모자라면 **되묻습니다.** 이미 해결된 건이면 중복으로 끊습니다 |
| 2 | MES 조회 | 제품명·로트로 검사 이미지를 찾습니다. **조인으로 답합니다** |
| 3 | 추론 | 그 품목의 뱅크로 판정해 미검·과검을 가려냅니다 |
| 4 | 판별 7항목 | 원인을 가리기 위한 근거 일곱을 모읍니다 |
| 5 | 진단 | 원인 6종 중 하나를 정합니다. **근거가 모자라면 판정하지 않습니다** |
| 6 | 큐레이션 | 뱅크에서 무엇을 빼고 무엇을 넣을지 정합니다 |
| 7 | 재구성 | 후보 뱅크를 만듭니다. **배포가 아닙니다** |
| 8 | 게이트 | 통과 기준과 대조합니다 |
| 9 | 섀도 | 신·구 뱅크를 같은 이미지에 병렬로 돌려 **판정이 갈린 건만** 뽑습니다 |
| 10 | 승인 요청 | 배포 패키지와 승인 요청 문서를 만들고 **멈춥니다** |

### 열 단계가 전부 도구입니다

언어 모델이 **어떤 도구를 어떤 순서로 부를지**를 정합니다. 판정 내용은
도구 안의 규칙이 냅니다.

- 모델이 순서를 어기면 도구가 거부합니다 — *"먼저 run_checks 를 불러야 한다"*
- 계획이 뱅크를 안 건드리기로 했으면 모델이 재구성을 불러도 실행되지 않습니다

**실측** — RTX 4090 에서 `gemma4-12b-vision` 하나로 도구 열 개가 전부
불렸고 순서를 모델이 정했습니다(실행 151초).

## 3. 무엇으로 판단하나

### 미검출 원인 6종

| 원인 | 판별 방법 | 조치 | 뱅크 재구성 |
|---|---|---|---|
| 임계값 문제 | 이상 점수는 높으나 임계값 아래 | 임계값 재조정 | 불필요 |
| 뱅크 오염 | 최근접 정상 패치가 실제로는 결함 | 혼입 이미지 제거 후 재구성 | **필요** |
| 커버리지 부족 | 현재 조건의 정상 패치가 뱅크에 없음 | 해당 조건 이미지 추가 | **필요** |
| 정상 분포 중첩 | 최근접 패치가 진짜 정상품인데 형상이 유사 | 기준 재정의·전용 로직·촬영 개선 | 효과 없음 |
| 설비·광학 | 화질 지표가 기준 분포를 이탈 | 설비 점검 요청 | 차단 |
| 기준 문제 | 검출은 했으나 기준상 양품 | 판정 기준 재정의 | 차단 |

**여섯 중 넷은 뱅크를 다시 만드는 것이 답이 아닙니다.** 진단 성능의 시험대는
"재학습을 해야 할 때 하는가"가 아니라 **"하지 말아야 할 때 멈추는가"** 에
있습니다.

### 판별 항목 7가지

| # | 무엇을 보나 | 무엇이 답하나 |
|---|---|---|
| 1 | 결함이 이미지에 실제로 보이는가 | 시각 언어 모델 |
| 2 | 화질 지표가 기준 분포를 벗어났는가 | 통계 비교 |
| 3 | 이상 점수가 임계값 대비 어디인가 | 조회 |
| 4 | 최근접 정상 패치가 무엇인가 | 뱅크 역추적 |
| 5 | 그 패치가 결함인가 진짜 정상품인가 | 시각 언어 모델 |
| 6 | 현재 조건의 정상 패치가 뱅크에 있는가 | 조회 |
| 7 | 판정 기준상 불량이 맞는가 | 기준 테이블 대조 |

**4번과 5번이 함께 작동하는 지점이 핵심입니다.** 최근접 패치를 찾는 것만으로는
부족하고, 그것이 **잘못 들어간 결함인지 진짜 정상품인지**를 구분해야 원인이
정해집니다 — 결함이면 뱅크 오염, 정상품이면 정상 분포 중첩이고 **조치가
정반대**입니다.

### 어디가 모델이고 어디가 규칙인가

**시각 언어 모델을 쓰는 것은 판별 1번과 5번뿐**이고 나머지는 조회와 계산
입니다. 원인 판정은 **규칙**이 하고 언어 모델은 **서술만** 합니다.

판정까지 모델에 맡기면 진단이 인상 평가가 됩니다. 판별 항목의 값은 조회와
계산에서 정확하게 나오므로, 그것을 어떻게 조합하는지는 코드로 적어 두는
편이 검증 가능하고 재현 가능합니다.

**조회 방식 실측 비중** — 조인 8 · 그래프 2 · 집계 1. 그래프 검색은 과거
이슈 이력 하나뿐이고 **역할은 중복 차단**입니다. MES 와 이미지 메타데이터는
벡터화하지 않습니다 — 조인으로 정확히 답할 문제이고, 임베딩하면 비슷한
로트를 섞어 옵니다.

## 4. 실행하는 법

### 준비

```bash
git clone <저장소>
cd SK_AI_Hackathon
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

**Python 3.11 기준**입니다. GPU 를 쓰려면 `requirements.txt` 위쪽 주석대로
cu126 인덱스에서 torch 를 다시 설치해야 합니다.

VisA 데이터셋(1.8GB)을 저장소 아래에 풀면 실데이터로 서고, 없으면 합성
이미지로 섭니다. **어느 쪽으로 섰는지는 화면에 그대로 표시됩니다.**

```bash
curl -O https://amazon-visual-anomaly.s3.amazonaws.com/VisA_20220922.tar
python data/build_factory.py --no-images    # 가상 공장 CSV (1.6초)
```

### 언어 모델 연결

로컬 모델과 외부 API 를 **설정으로 교체**합니다. 비워 두면 모델 없이 고정
순서로 실행되고, 화면에 *"순서를 모델이 정한 것이 아닙니다"* 라고 표시됩니다.

```bash
export SHVO_LLM_PROVIDER=openai_compat
export SHVO_LLM_BASE_URL=http://localhost:11434/v1
export SHVO_LLM_MODEL=gemma4-12b-vision
export SHVO_VLM_PROVIDER=openai_compat
export SHVO_VLM_BASE_URL=http://localhost:11434/v1
export SHVO_VLM_MODEL=gemma4-12b-vision   # 멀티모달이라 같은 이름
```

### 실행

```bash
python scripts/check_models.py                  # 모델 연결·도구 호출·이미지 판독
python scripts/run_demo.py                      # 전 구간 한 번 (글로 출력)
python -m uvicorn app.main:app --port 8000      # 웹 화면
python scripts/run_scheduler.py --now           # 야간 누적분 자동 점검
```

### 확인

```bash
python -m pytest tests/ -q            # 전체 시험
python scripts/check_all.py           # 시험·문서·데이터·시나리오·공개 준비
python scripts/measure_rules.py       # 진단 규칙 정확도 채점
```

자세한 절차는 [`docs/운영_표준절차.md`](운영_표준절차.md) 에 있습니다.

## 6. 무엇을 안 하는가

**무인 배포를 만들지 않았습니다.** 릴리즈 에이전트는 배포 패키지와 승인 요청
문서까지만 만듭니다. 품질 검사 설비의 특성상 의도적으로 배제했고, **그 경계를
코드가 지킵니다** — 에이전트와 스케줄러에 배포로 읽히는 함수가 생기면 시험이
실패합니다.

승인 뒤 전환도 사람이 명령을 실행합니다. 그때 **누가·왜가 없으면 거부**됩니다.

```bash
python scripts/switch_bank.py --item pcb1-01 --to <판 이름> \
    --by <이름> --reason "ISS-0051 뱅크 오염. 게이트 통과, 섀도 1건"
```

되돌리기는 **가리키는 이름 한 줄**만 바꿉니다. 파일이 움직이지 않으므로 도중에
멈춰도 운영본을 잃지 않고, 되돌린 뒤에도 새 판이 남아 다시 앞으로 갈 수
있습니다.

**사내 데이터를 쓰지 않습니다.** 모든 데이터는 VisA 공개 데이터셋과 직접
생성한 가상 데이터입니다.

## 7. 실측으로 확인된 것

숫자는 **측정 조건과 함께** 읽어야 합니다. 조건이 다르면 나란히 놓을 수
없습니다.

### 임계값 스윕은 "푼 줄 알게" 만든다

```
VisA pcb1 · 정상 150장 · 혼입 3장(2.0%) · 512 정사각 · 홀드아웃 50/12

오염된 뱅크    AUROC 1.000 · 스윕 "해결 가능"(과검 0%)
              그런데 운영 임계값에서 검출 0/12
```

뱅크 오염이 이상 점수를 24.4% 끌어내려 전건이 임계값 아래로 갔는데 **두 지표가
모두 통과**입니다. 스윕은 틀린 답을 준 것이 아닙니다 — 임계값을 내리면 실제로
검출됩니다. 문제는 그 답이 **원인을 고치지 않고**, **임계값 문제일 때와 완전히
같다**는 것입니다.

### 역추적은 오염이 해를 끼쳤을 때 짚는다

```
pcb1      오염이 점수를 끌어내림  →  미검 12건이 전부 혼입 이미지 지목 (12/12)
capsules  점수 하락 없음         →  한 번도 지목 안 함 (0/12)
```

**capsules 는 반례가 아닙니다.** 뱅크에 결함이 섞여 있어도 판정에 영향을
주지 않았으므로 그 미검의 원인이 아니었고, **지목하지 않은 것이 옳습니다.**

### coreset 이 끌어올리는 것은 결함이 아니다

```
혼입률 3.2%   그 출신 패치가 뱅크에서 14.2% (4.4배)   결함 **위** 패치는 0.3%
혼입률 11.8%                        31.1% (2.6배)                     1.6%
```

혼입 이미지 출신은 부풀지만 **결함 그 자체는 0.3%** 입니다. 그래서 통계로
훑어서는 못 찾고 **미검출 건들의 반복 지목**이 찾습니다. 그리고 이미지 단위로
빼면 정상부 98.2% 를 함께 버립니다.

### 판별 5번 하나가 조치를 반대로 돌린다

같은 이미지·같은 점수에서 판별 5번만 바꿔 두 번 실행했습니다.

| 판별 5번 | 원인 | 뱅크 재구성 | 금지 |
|---|---|---|---|
| 진짜 정상품 | 임계값 문제 | **하지 않음** | 임계값 인하 |
| 잘못 들어간 결함 | 뱅크 오염 | **필요** | — |

### 섀도가 확인 대상을 줄인다

14장을 두 뱅크로 병렬 추론해 갈린 것 **1장**. 그 한 장의 이상 점수가
2.135 → 2.969 로 올라 검출됐습니다. **정답 라벨 없이** 개선을 보여주고,
사람이 확인한 그 한 장이 정답 라벨이 됩니다.

### 진단 규칙 정확도

```
원인 일치        22/24 (92%)
재구성 여부 일치  22/24
금지 행위 위반    0건
```

**금지 행위 위반 0건이 가장 중요한 값**입니다. 재구성하면 안 되는 케이스에서
한 번도 재구성을 지시하지 않았습니다. 다만 이 값이 0인 것은 원인과 조치의
대응이 테이블로 고정돼 있어 **설계로 보장한** 것이기도 합니다.

**이미지도 뱅크도 모델도 쓰지 않은 값입니다.** 정답 근거를 그대로 규칙에
넣어 잰 것이므로 **규칙의 정확도**이지 전 구간 정확도가 아닙니다.

## 8. 알려진 한계

**숨기면 심사에서 파고들었을 때 무너집니다.** 정직하게 적습니다.

### 판별 1번이 기판에서 위치를 잘 못 짚습니다

```
pcb1 · 역추적 상위 1자리 크롭으로 판독      3/10
     · 자리별 기준선을 뺀 뒤 상위 5자리      5/10
```

**위치 추정을 다듬는 세 방법이 전부 5/10 을 못 넘습니다.**

모델 탓이 아니라는 근거는 **12품목 전체 측정**에 있습니다.

```
정답 마스크로 잘라 주면 (결함 있음)     80.8%   (97/120)
정상 이미지 무작위 크롭 (결함 없음)     10.8%   (13/120)
결함 이미지의 결함 비껴간 크롭          11.0%   (13/118)
```

**자리를 주면 81%, 엉뚱한 자리를 주면 11% — 7.4배 갈립니다.** "확대된
조각이면 무조건 결함이라 한다"가 아니라는 뜻이고, 동시에 **역추적이 자리를
놓치면 판독이 11% 로 떨어진다**는 뜻입니다.

그래서 판별 1번이 실제보다 자주 보류되고, 그때 **진단이 멈춥니다.**

**멈추는 것은 고장이 아닙니다** — 결함이 안 보이면 접수 오류일 수 있고, 그
상태에서 원인을 정하면 엉뚱한 이미지로 뱅크를 고치게 됩니다.

### 판별 5번이 실제로는 "결함"을 잘 못 냅니다

역추적은 혼입 이미지를 정확히 지목하는데, **지목된 그 패치 자리가 대개 그
이미지의 멀쩡한 부분**입니다(혼입 5장이 남긴 903개 중 결함 위 16개, 1.8%).
시각 언어 모델이 "진짜 정상품"이라 답하는 것이 틀린 답이 아닙니다.

시연에서는 판별 5번을 손으로 지정해 갈림을 보여주며, **손으로 넣은 값이라는
표시가 화면에 그대로 나옵니다.**

### 아직 값이 정해지지 않은 것

| 무엇 | 상태 |
|---|---|
| 판정 기준 면적 임계값 | 면적 계산 방식을 바꿔 **재측정 대기** |
| 화질 노이즈 산출식 | 미정 |
| 승인 권한 | 조직이 정할 일 |

### 채점의 독립성

진단 정확도가 의미를 갖는 이유는 **정답을 다른 사람이 썼기 때문**입니다.
개발 후반에 역할이 한 사람에게 모이면서 규칙과 기준을 같은 사람이 정하게
됐고, 그만큼 이 숫자의 무게가 줄었습니다. 그 사실을 함께 적습니다.

### 측정 조건이 바뀐 값들

입력 전처리에서 중앙 크롭을 뺐습니다(VisA 는 가로가 길어 **결함이 실제로
잘려 나가고 있었습니다** — pcb3 은 40건 중 12건이 일부, capsules 는 1건이
통째로). 그 전에 잰 AUROC 는 지금 시스템의 값이 아니라 **재측정 대기**입니다.
