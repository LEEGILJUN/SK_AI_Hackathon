# 기판에서도 512 로 충분한가

측정 2026-08-14 · RTX 4090 Laptop · CUDA · `scripts/measure_auroc.py`
맥(mps) 대조 포함.

---

## 0. 왜 쟀나

**실측이 전부 capsules 였는데 팀 데이터는 전부 pcb 였다.**

- 해상도 표(0.526 → 0.998), coreset 증폭 반증, 판별 5번, 역추적 크롭 — 전부 capsules
- 장영진 시나리오 24건 · 이동현 공장 데이터 — 전부 pcb1~4

기판은 캡슐과 조건이 다르다. **화면의 절반 이상이 배경**이고(회색 펠트·초록·검정),
결함이 0402 저항 하나 빠진 수준으로 더 작다. 캡슐에서 256/224 가 0.526(무작위
수준)이었던 함정이 **해상도만 한 칸 옮겨서 기판에서 재현될 수 있었다.**

나쁘게 나오면 시나리오 24건이 통째로 흔들리므로 순서상 제일 먼저였다.

---

## 1. 측정 조건 — 결과와 함께 인용할 것

```
해상도    512/448 (FeatureConfig 기본값)
백본      wide_resnet50_2 · layers ['layer2','layer3']
coreset   0.01  (seed 0)
뱅크 오염      0장 (깨끗한 뱅크)

뱅크 정상    150장  = sorted(Normal/*.JPG)[0:150]
홀드아웃     정상 25장 = sorted(Normal/*.JPG)[150:175]   ← 뱅크와 겹치지 않음
             결함 25장 = sorted(Anomaly/*.JPG)[0:25]

AUROC       inspection.sweep.sweep_thresholds().auroc()
```

**`demo_trace.py` 로는 이 표를 못 만든다.** 그쪽은
`holdout_size = len(normal)//4` 로 나누고 결함을 12장만 쓴다 — 정상 150장을
주면 뱅크 113 · 홀드아웃 37/12 가 된다. 그래서 `scripts/measure_auroc.py` 를
따로 만들어 뱅크와 홀드아웃을 겹치지 않게 떼어 냈다.

무작위로 뽑지 않고 **파일명 정렬 순서**를 쓴다. 같은 명령이 같은 수치를 내야
하기 때문이다.

## 2. 결과 — 우려가 재현되지 않았다

| 카테고리 | AUROC | 정상 중앙 | 결함 중앙 | 겹침 |
|---|---|---|---|---|
| pcb1 | **1.000** | 1.798 | 3.172 | 없음 |
| pcb2 | **0.998** | 1.906 | 2.714 | 있음 |
| pcb3 | **1.000** | 1.977 | 3.033 | 없음 |
| pcb4 | **1.000** | 1.834 | 2.646 | 없음 |
| capsules | 0.989 | 2.280 | 2.562 | 있음 |

**기판 넷이 모두 캡슐보다 높고 셋은 정상·결함 점수가 아예 겹치지 않는다.**
512 가 모자랄 것이라는 우려는 반대로 나왔다.

**768/672 는 재지 않았다.** 512 가 모자란 카테고리가 없어 조건이 성립하지
않는다. 혹시나 해서 재면 그 숫자가 표에 남아 나중에 근거로 오용된다.
필요하면 `--resize 768 --crop 672` 로 같은 스크립트가 돈다.

### capsules 0.989 는 기존 표의 0.998 과 다르다

파라미터가 같은데 0.009 차이가 난다. **원 측정이 어느 25장을 홀드아웃으로
썼는지 기록돼 있지 않기 때문이다.**

`CLAUDE.md` 가 *"AUROC 는 홀드아웃 구성이 다르면 직접 비교할 수 없다"* 고 적어
두고 **정작 그 구성을 안 남긴 셈**이다. 이번 분할은 스크립트 독스트링에
못박았으므로 다음부터는 재현된다. 기존 표의 0.998 은 그대로 두되 **조건이 다른
값**으로 읽어야 한다.

## 3. 교차 측정 — 이쪽이 더 크다

pcb1 과 pcb2 는 **같은 보드(HC-SR04)의 앞면과 뒷면**이고 배경·조명이 같다.
그래서 점수가 뜨는 이유가 "배경이 달라서"가 아니라 **"정상 패치가 달라서"**
하나로 좁혀진다. pcb3(초록)·pcb4(검정)는 배경까지 달라 이 비교에 안 맞는다.

```
pcb1 뱅크 4,704행 으로 두 무리를 잰다

무리                        장수      최소      중앙      최대
pcb1 정상 (같은 카테고리)      25    1.708    1.798    2.104
pcb2 정상 (다른 카테고리)      25    3.421    3.527    3.643

두 무리의 분리도 AUROC 1.000
겹침 없음: pcb2 최소 3.421 vs pcb1 최대 2.104  →  완전히 갈림
```

**pcb2 정상의 최솟값(3.421)이 pcb1 결함의 중앙값(3.172)보다 높다.** pcb1 의
진짜 결함 절반 이상이 pcb2 의 어떤 정상품보다도 낮은 점수를 받는다.

### 무엇을 뒷받침하나

**뱅크는 라인마다 따로여야 한다** — `receive(duplicate_requires_same_line=True)`
와 `decide(current_line=...)` 의 근거다. 같은 품목이어도 1라인 뱅크가 오염됐다고
2라인도 그렇다는 뜻이 아니다. 유사도만 보고 끊으면 실제로 있는 문제를 "이미
해결된 건"으로 덮는다.

**뒤집으면 위험 신호다.** `lookup.resolve_bank` 가 품목을 잘못 물면 **전 건이
불량으로 뜬다**(과검 100%). 조용히 틀리지 않아 알아채기는 쉽지만, 시연이
통째로 무너진다는 뜻이다.

## 4. 장치가 달라도 재현되는가 — 맥(mps) 대조

| | 4090 (cuda) | 맥 (mps) |
|---|---|---|
| pcb1 AUROC | 1.000 | **1.000** |
| 뱅크 행수 | 4,704 | **4,704** |
| pcb1 정상 중앙 | 1.798 | 1.812 |
| pcb1 결함 중앙 | 3.172 | 3.143 |
| 교차 pcb2 정상 | 3.421 / 3.527 / 3.643 | **3.421 / 3.527 / 3.643** |
| 겹침 | 없음 | **없음** |

**뱅크 행수가 정확히 같은 것이 핵심이다.** greedy coreset 이 장치를 타지
않는다는 뜻이고, `agents/gate.py` 의 재현성 검사가 실제로 설 근거다.
점수는 부동소수점 차이로 갈리지만 판정(AUROC·겹침)은 안 바뀐다.

갈리는 폭이 무리마다 다르다. 뱅크와 **같은** 카테고리(pcb1 정상)는 셋째 자리가
움직이고 **다른** 카테고리(pcb2 정상)는 그대로다. 최근접 거리가 작을수록 상대
오차가 크게 보이는 것으로 읽히지만 **확인한 것은 아니다 — 관찰이지 설명이 아니다.**

## 5. 다시 재는 법

```bash
python scripts/measure_auroc.py --categories pcb1 pcb2 pcb3 pcb4 capsules
python scripts/measure_auroc.py --cross pcb1:pcb2
```

**측정 조건이 결과와 함께 찍힌다.** 조건 없는 AUROC 는 나중에 쓸 수 없다는
것이 이 실험이 다시 확인한 교훈이다(2장 끝).
