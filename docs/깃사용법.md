# 깃 사용법 — 처음 쓰는 사람용

이 프로젝트에서 **실제로 필요한 것만** 담았습니다. 깃을 배우는 문서가 아니라, 자기 작업을 저장소에 올리고 남의 작업을 받아오는 데 필요한 최소한입니다.

읽는 순서대로 따라 하면 됩니다. 막히면 이길준에게 물어보세요.

---

## 0. 시작하기 전에 — 초대를 먼저 받으세요

저장소가 **비공개(private)** 라서, 초대를 받지 않으면 주소를 열어도 404가 뜨고 클론도 안 됩니다.

이길준이 GitHub에서 `Settings → Collaborators → Add people`로 초대하면, 등록한 메일로 초대장이 옵니다. **그 링크를 눌러 수락해야** 접근이 열립니다.

> 초대 수락 전에는 아래 내용이 전부 실패합니다. 이것부터 확인하세요.

---

## 1. 세 가지 방법 중에 고르기

하려는 일에 따라 방법이 다릅니다. **전부 배울 필요 없습니다.**

| 하려는 일 | 방법 | 설치 필요 |
|---|---|---|
| README 체크박스 표시, 문서 오타 수정 | **A. GitHub 웹에서 직접 편집** | 없음 |
| 코드 작성, 파일 여러 개 수정, 데이터 생성 | **B. GitHub Desktop** (권장) | 프로그램 1개 |
| 익숙해진 뒤 | C. 명령어 | — |

문서만 고칠 거면 A만 알면 됩니다. 깃을 설치할 필요도 없습니다.

---

## 2. 방법 A — GitHub 웹에서 직접 편집

**가장 쉽습니다. README 체크박스 표시와 문서 수정은 이걸로 하세요.**

### 순서

1. 브라우저에서 저장소를 엽니다 → https://github.com/LEEGILJUN/SK_AI_Hackathon
2. 고칠 파일을 클릭합니다. (예: `README.md`)
3. 파일 내용 오른쪽 위의 **연필 아이콘(✏️)** 을 누릅니다.
4. 편집창에서 내용을 고칩니다.
5. 오른쪽 위 초록색 **`Commit changes...`** 버튼을 누릅니다.
6. 작은 창이 뜹니다. 첫 칸에 **무엇을 바꿨는지 한 줄**로 씁니다.
   - 예: `체크: 이동현 1번 완료`
   - 예: `오타 수정`
7. 아래 **`Commit directly to the main branch`** 가 선택된 상태 그대로 두고, **`Commit changes`** 를 누릅니다.

끝입니다. 바로 반영됩니다.

### 체크박스 표시하는 법

README에서 자기 항목을 찾아 대괄호 안에 `x`만 넣으면 됩니다.

```
- [ ] 1. VisA 확보 및 가상 공장 폴더트리 구성      ← 아직 안 함
- [x] 1. VisA 확보 및 가상 공장 폴더트리 구성      ← 완료
```

> **주의:** README에 보이는 네모 상자는 **눌러도 체크되지 않습니다.** 위처럼 글자를 직접 고쳐야 합니다. (GitHub에서 클릭이 되는 건 이슈·PR 본문뿐입니다.)

### 새 파일 만들기

저장소 첫 화면에서 **`Add file → Create new file`** 을 누릅니다.
파일 이름 칸에 `docs/화질지표정의.md` 처럼 **폴더까지 같이** 적으면 폴더가 자동으로 만들어집니다.

## 3. 방법 B — GitHub Desktop (코드 작업용)

코드나 데이터 파일을 다룰 때는 내 컴퓨터에 받아놓고 작업해야 합니다. 명령어 없이 버튼으로 다 됩니다.

### 3-1. 설치와 최초 설정 (처음 한 번만)

1. https://desktop.github.com 에서 내려받아 설치합니다. (Mac / Windows 둘 다 있음)
2. 실행하면 로그인 화면이 나옵니다. **`Sign in to GitHub.com`** → 브라우저에서 로그인 → 승인.
   - 이 과정에서 인증이 자동으로 처리됩니다. 비밀번호를 따로 입력할 일이 없습니다.
3. 이름과 이메일을 확인하는 화면이 나오면 그대로 `Finish`.

### 3-2. 저장소 받아오기 (처음 한 번만)

1. 상단 메뉴 **`File → Clone repository`**
2. **`GitHub.com`** 탭에서 목록 중 **`LEEGILJUN/SK_AI_Hackathon`** 을 고릅니다.
   - 목록에 없으면 초대를 아직 수락하지 않은 것입니다. 0번으로 돌아가세요.
3. **`Local path`** 는 저장할 위치입니다. 기본값 그대로 두어도 됩니다. 경로를 기억해 두세요.
4. **`Clone`** 을 누릅니다.

이제 그 폴더 안에 저장소 내용이 전부 들어 있습니다. **파일 편집은 평소 쓰던 편집기(VS Code, 메모장 등)로 그 폴더를 열어서 하면 됩니다.**

### 3-3. 매일 반복하는 4단계

이게 전부입니다. 이 순서만 지키면 사고가 안 납니다.

```
① 받아오기  →  ② 작업하기  →  ③ 기록하기  →  ④ 올리기
   Pull          편집기            Commit         Push
```

**① 작업 시작 전에 받아오기 (제일 중요)**

GitHub Desktop을 열고 상단의 **`Fetch origin`** 을 누릅니다.
받을 게 있으면 버튼이 **`Pull origin`** 으로 바뀝니다. 한 번 더 누릅니다.

> **이걸 건너뛰면 충돌이 납니다.** 남이 고친 걸 안 받고 같은 파일을 고치면 나중에 부딪힙니다. 습관으로 만드세요.

**② 편집기로 파일을 고칩니다**

평소대로 작업하면 됩니다. 저장만 하면 GitHub Desktop이 알아서 변경을 감지합니다.

**③ 기록하기 (Commit)**

1. GitHub Desktop으로 돌아오면 왼쪽에 **바뀐 파일 목록**이 보입니다.
2. 올릴 파일만 체크합니다. (보통 전부 체크된 상태 그대로 두면 됩니다)
3. 왼쪽 아래 칸에 **무엇을 했는지 한 줄** 적습니다.
   - 예: `가상 MES 데이터 생성 스크립트 추가`
   - 예: `화질 지표 기준 분포 산출`
4. **`Commit to main`** 버튼을 누릅니다.

> 커밋은 **내 컴퓨터에만** 기록하는 것입니다. 아직 팀원에게 보이지 않습니다.

**④ 올리기 (Push)**

상단의 **`Push origin`** 을 누릅니다. 이제 팀원에게 보입니다.

> 커밋만 하고 푸시를 안 하면 아무도 못 봅니다. **작업이 한 덩어리 끝날 때마다 푸시하세요.** 하루에 여러 번이 좋습니다.

## 4. 이미 있는 파일·폴더를 고치는 방법

가장 많이 헷갈리는 부분입니다. **깃에서는 "수정"이라는 별도 동작이 없습니다.** 그냥 파일을 고치고 커밋하면 그게 수정입니다.

| 하려는 일 | 어떻게 |
|---|---|
| 기존 파일 내용 고치기 | 편집기로 열어서 고치고 저장 → 커밋 → 푸시 |
| 기존 파일에 내용 추가 | 위와 동일. 깃이 알아서 "어디가 늘었는지" 기록합니다 |
| 새 파일 만들기 | 해당 폴더 안에 파일을 만들고 저장 → 커밋 → 푸시 |
| 폴더 새로 만들기 | 폴더만 만들면 깃이 무시합니다. **안에 파일이 하나라도 있어야** 올라갑니다 |
| 파일 이름 바꾸기 | 그냥 이름을 바꾸면 됩니다. 깃이 알아서 인식합니다 |
| 파일 삭제 | 그냥 지우면 됩니다 → 커밋 → 푸시 |
| 남이 만든 파일 고치기 | 똑같습니다. 단, 아래 **소유권** 규칙을 먼저 확인하세요 |

### 폴더 구조는 그냥 폴더입니다

`agents/`, `inspection/`, `data/` 같은 건 특별한 게 아니라 보통 폴더입니다. 자기 담당 폴더 안에 파일을 만들면 됩니다.

```
SK_AI_Hackathon/
├─ data/       ← 이동현 (데이터 생성), 장영진 (yaml 기준 파일)
├─ inspection/ ← 이길준 (PatchCore 추론·역추적)
├─ agents/     ← 이길준 (에이전트)
├─ indexer/    ← 이동현 (학습 이력 인덱서)
├─ app/        ← 이길준 (웹 화면)
├─ scripts/    ← 공용 (뱅크 구성, 평가, 리포트)
└─ docs/       ← 공용 (문서)
```

각 폴더에 있는 `.gitkeep` 은 **빈 폴더를 저장소에 남겨두기 위한 빈 파일**입니다. 그 폴더에 진짜 파일이 생기면 지워도 되고, 그냥 둬도 됩니다.

### 소유권 — 남의 파일을 고치기 전에

| 파일 | 소유 | 규칙 |
|---|---|---|
| `data/scenarios.yaml` | 장영진 | **정답 파일.** 진단 정확도를 맞추려고 고치지 않습니다. 반드시 합의 후 |
| `data/criteria.yaml`, `data/quality_baseline.yaml` | 장영진 | 판정 기준의 단일 출처 |
| `data/build_factory.py`, `mes.csv`, `manifest.csv` | 이동현 | 데이터 생성의 단일 출처 |
| `agents/`, `inspection/` | 이길준 | 판정 로직과 추론 |

자기 것이 아니면 고치기 전에 한마디 하세요. 기술적으로는 막혀 있지 않지만, 말없이 고치면 서로 덮어씁니다.

## 5. 문제가 생겼을 때

### "Push가 안 됩니다" / `rejected` / `fetch first`

**원인:** 내가 올리려는 사이에 남이 먼저 올렸습니다.
**해결:** `Pull origin`을 먼저 누르고, 그다음 `Push origin`.

### 충돌(Conflict)이 났습니다

같은 파일의 **같은 줄**을 두 사람이 다르게 고쳤을 때 납니다. 깃이 어느 쪽이 맞는지 몰라서 사람에게 묻는 것이지, 고장 난 게 아닙니다.

GitHub Desktop이 충돌 파일을 알려줍니다. 그 파일을 편집기로 열면 이렇게 생겼습니다.

```
<<<<<<< HEAD
- [x] 4. 가상 MES 데이터 생성          ← 내가 쓴 것
=======
- [ ] 4. 가상 MES 데이터 생성 (진행중)  ← 남이 쓴 것
>>>>>>> origin/main
```

**할 일:** 남길 내용만 남기고, `<<<<<<<`, `=======`, `>>>>>>>` **세 줄을 전부 지웁니다.**

```
- [x] 4. 가상 MES 데이터 생성
```

저장한 뒤 GitHub Desktop에서 커밋하고 푸시하면 끝입니다.

> 겁먹지 마세요. 파일이 망가진 게 아니라 두 버전이 나란히 적혀 있을 뿐입니다.

### 잘못 고쳤습니다. 되돌리고 싶어요

**아직 커밋 안 했으면:** GitHub Desktop 왼쪽 파일 목록에서 해당 파일을 **우클릭 → `Discard changes`**. 마지막 커밋 상태로 돌아갑니다.

**이미 커밋·푸시했으면:** 되돌릴 수 있지만 방법이 여러 가지입니다. **직접 하지 말고 이길준에게 말하세요.** 깃은 기록이 남는 구조라 거의 다 복구됩니다.

### 실수로 큰 파일을 올렸습니다

VisA 이미지나 뱅크 파일(`.pt`, `.npz`)은 `.gitignore`에 등록돼 있어서 **자동으로 걸러집니다.** 신경 쓰지 않아도 됩니다.

혹시 GitHub Desktop 파일 목록에 이미지가 수백 개 뜬다면 뭔가 잘못된 것입니다. **커밋하지 말고** 이길준에게 알려주세요.

## 6. 이 프로젝트에서 하지 말 것

- **VisA 원본 이미지, 메모리 뱅크 파일(`.pt`/`.npz`), 실행 로그를 커밋하지 않습니다.** 용량이 크고 GitHub 제한에 걸립니다. 데이터는 스크립트로 다시 만듭니다.
- **`data/scenarios.yaml`을 임의로 고치지 않습니다.** 채점 기준 파일입니다.
- **사내 데이터를 넣지 않습니다.** 실제 공정 조건, 장비 공급사명, 생산 거점, 사내 결함 정의는 코드·주석·문서 어디에도 넣지 않습니다.
- **저장소를 공개로 바꾸지 않습니다.** 대회 기간 중 비공개 유지입니다.

## 7. 용어 (최소한만)

| 말 | 뜻 |
|---|---|
| 저장소 (repository, repo) | 프로젝트 폴더 전체 + 변경 기록 |
| 클론 (clone) | 저장소를 내 컴퓨터로 복사해 오기. 처음 한 번만 |
| 풀 (pull) | 남이 올린 최신 내용을 내 컴퓨터로 받아오기 |
| 커밋 (commit) | 지금까지 고친 것을 **내 컴퓨터에** 기록으로 남기기 |
| 푸시 (push) | 내 커밋을 **GitHub에 올려** 팀원에게 보이게 하기 |
| main | 기본 작업 줄기. 우리는 여기 하나만 씁니다 |
| 충돌 (conflict) | 같은 줄을 두 사람이 다르게 고쳐서 깃이 판단을 못 하는 상태 |

우리는 브랜치를 쓰지 않고 **전원이 `main`에 바로 올립니다.** 2주짜리 일정에 담당 폴더가 갈려 있어서 그게 단순하고 빠릅니다. 대신 **작업 전에 Pull** 이 습관이어야 합니다.

## 부록 — 명령어로 하고 싶다면

터미널이 편한 사람만 보세요. 위 GitHub Desktop 버튼과 하는 일이 같습니다.

```bash
# 처음 한 번만 — 내 정보 등록
git config --global user.name "홍길동"
git config --global user.email "본인메일@example.com"

# 처음 한 번만 — 저장소 받아오기
git clone https://github.com/LEEGILJUN/SK_AI_Hackathon.git
cd SK_AI_Hackathon
```

```bash
# 매번 반복하는 4단계
git pull                          # ① 남의 작업 받아오기 (작업 시작 전 필수)
                                  # ② 편집기로 파일 수정
git add -A                        # ③ 바뀐 것 전부 담기
git commit -m "무엇을 했는지 한 줄"   #    기록 남기기 (아직 내 컴퓨터에만)
git push                          # ④ GitHub에 올리기
```

```bash
# 상태 확인
git status                        # 지금 뭐가 바뀌었나
git log --oneline -10             # 최근 커밋 10개

# 되돌리기 (커밋 전)
git restore 파일이름                # 그 파일 수정을 버리고 마지막 커밋 상태로
```

명령어로 클론할 때 아이디·비밀번호를 물으면, GitHub 비밀번호는 **더 이상 동작하지 않습니다.** GitHub Desktop을 설치해 로그인해 두거나, `gh auth login`(GitHub CLI)으로 인증을 한 번 잡아두세요.
