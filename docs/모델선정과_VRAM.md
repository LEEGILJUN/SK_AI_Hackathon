# 모델 선정과 VRAM 예산

작성 2026-08-14 · 이길준
대상 장비: **RTX 4090 Laptop · VRAM 16GB**

시연도 개발도 이 한 대에서 돕니다. 그래서 "어느 모델이 좋은가"보다
**"무엇이 16GB 안에서 함께 도는가"** 가 먼저입니다.

---

## 1. 결론

| | 선택 | 근거 |
|---|---|---|
| **1순위** | Gemma 4 12B (Q6_K 또는 QAT-Q4) 단독 | 멀티모달 + 네이티브 도구 호출. **하나로 LLM·VLM 둘 다** |
| **대안** | Qwen3-14B + Qwen3-VL-8B | 현재 구성. VLM 쪽은 검증됨. 합 14.2GB |
| **탈락** | Gemma 4 26B-A4B, 31B / Qwen3.5·3.6 27B 이상 | 16GB 초과 |

**Gemma 4 12B 가 되면 구조가 단순해집니다.** 모델 하나, 스왑 없음,
VRAM 절반. 다만 **도구 호출과 40px 결함 판독이 실제로 되는지는 아직
측정하지 않았습니다.** 그게 다음 실험입니다.

---

## 2. 실측한 파일 크기

HuggingFace 저장소에서 직접 확인한 값입니다. 파라미터 수가 아니라
**실제 GGUF 파일 크기**로 판단해야 합니다.

### Gemma 4 12B (`unsloth/gemma-4-12b-it-GGUF`)

| 양자화 | 본체 | mmproj(F32) | 합계 |
|---|---|---|---|
| UD-IQ2_M | 4.21GB | 0.21 | 4.4GB |
| Q3_K_M | 5.69GB | 0.21 | 5.9GB |
| **QAT UD-Q4_K_XL** | 6.72GB | 0.21 | **6.9GB** |
| Q4_K_M | 7.12GB | 0.21 | 7.3GB |
| Q5_K_M | 8.41GB | 0.21 | 8.6GB |
| **Q6_K** | 9.79GB | 0.21 | **10.0GB** |
| Q8_0 | 12.7GB | 0.21 | 12.9GB |
| BF16 | 23.8GB | 0.21 | 초과 |

### Gemma 4 26B-A4B (`unsloth/gemma-4-26B-A4B-it-GGUF`)

| 양자화 | 본체 | mmproj(F16) | 합계 |
|---|---|---|---|
| UD-IQ2_XXS | 9.92GB | 1.19 | 11.1GB |
| UD-Q2_K_XL | 10.5GB | 1.19 | 11.7GB |
| UD-IQ3_S | 11.3GB | 1.19 | 12.5GB |
| UD-Q3_K_M | 12.7GB | 1.19 | 13.9GB |
| UD-IQ4_XS | 13.6GB | 1.19 | 14.8GB |
| **QAT UD-Q4_K_XL** | 14.2GB | 1.19 | 15.4GB |
| UD-Q4_K_S 이상 | 16.5GB+ | — | 초과 |

**`A4B` 는 토큰당 활성 파라미터가 4B 라는 뜻입니다. 속도는 4B 급이지만
메모리는 26B 전부를 올려야 합니다.** 빠른 것과 작은 것은 다릅니다.

### mmproj 는 별도 파일입니다 — 이게 함정이었습니다

Gemma 4 는 비전 투영기(mmproj)가 본체와 분리돼 있습니다. **본체만 받으면
눈이 없는 텍스트 모델이 됩니다.**

4090 에 `gemma4-26b`·`gemma4-31b` 가 "투영기 없음"으로 깔려 있던 것이
정확히 이 이유입니다. 모델 결함이 아니라 mmproj 를 안 받은 것입니다.

| 모델 | mmproj F16 | mmproj F32 |
|---|---|---|
| 12B | 175MB | 210MB |
| 26B-A4B | 1.19GB | 2.29GB |

12B 는 175MB 인데 26B 는 1.19GB 입니다. 비전 인코더 구조가 다릅니다.

## 3. VRAM 예산 — 모델만 보면 안 됩니다

같은 카드에서 여러 개가 동시에 돕니다.

| 쓰는 것 | 크기 | 언제 |
|---|---|---|
| Ollama 모델 가중치 | 6.9~12.9GB | 상주 |
| KV 캐시 | 1~2GB (8K 컨텍스트) | 상주. 컨텍스트 늘리면 급증 |
| 이미지 인코딩 활성 | 수백MB | 판독 중 순간 |
| CUDA 컨텍스트 (torch) | 0.3~0.5GB | 상주 |
| PatchCore 추론 | **0.4GB** | 추론 중 |
| PatchCore 뱅크 구축 | **~1GB** | 재구성 중 |

### PatchCore 쪽 실측 (텐서 크기 계산, 장치 무관)

설정 512/448, 격자 56×56 = 패치 3,136/장, 차원 1,536.

| 정상 장수 | 전체 패치 | 평탄 텐서 (**CPU RAM**) | 사영 텐서 (**VRAM**) |
|---|---|---|---|
| 60 | 188,160 | 1.08GB | 0.09GB |
| 113 | 354,368 | 2.03GB | **0.17GB** |
| 150 | 470,400 | 2.69GB | 0.22GB |
| 300 | 940,800 | 5.38GB | 0.45GB |
| 600 | 1,881,600 | 10.77GB | 0.90GB |

**큰 텐서는 VRAM 이 아니라 CPU RAM 에 있습니다.**
`features.py` 의 `embed_paths()` 가 `patches.cpu()` 로 내리고,
`bank.py` 의 `greedy_coreset()` 은 **128차원으로 사영한 뒤에만** GPU 로
올립니다. 그래서 뱅크 구축 중 VRAM 은 1GB 안팎입니다.

다만 **CPU RAM 은 실제로 씁니다.** 정상 600장이면 10.8GB 라 시스템 메모리를
봐야 합니다.

추론 정상 상태는 더 작습니다.

```
뱅크 상주(3,544행)  0.020GB
질의 패치           0.018GB
cdist 청크          0.096GB
백본 가중치         ~0.27GB
→ 합계 약 0.40GB
```

### 조합별 합계

| 구성 | 모델 | KV | torch | 합계 | 판정 |
|---|---|---|---|---|---|
| **12B QAT Q4** | 6.9 | 2.0 | 1.0 | **9.9GB** | 여유 |
| **12B Q6_K** | 10.0 | 2.0 | 1.0 | **13.0GB** | 3GB 여유 |
| 12B Q8_0 | 12.9 | 2.0 | 1.0 | 15.9GB | 위험 |
| Qwen3-14B + Qwen3-VL-8B | 14.2 | 2.0 | 1.0 | 17.2GB | **초과** ⚠ |
| 26B-A4B Q3_K_M | 13.9 | 2.0 | 1.0 | 16.9GB | 초과 |
| 26B-A4B IQ3_S | 12.5 | 2.0 | 1.0 | 15.5GB | 위험 |
| 26B-A4B Q2_K_XL | 11.7 | 2.0 | 1.0 | 14.7GB | 품질 미지수 |

> **현재 구성(Qwen 둘)도 KV 캐시를 넣으면 초과합니다.** 지금 도는 것은
> 컨텍스트가 짧아서일 가능성이 큽니다. 긴 프롬프트에서 터질 수 있으니
> `num_ctx` 를 확인해야 합니다.

## 4. VRAM 이 모자랄 때 쓸 수 있는 것

순서대로 시도합니다.

1. **`num_ctx` 를 8K 로 제한** — KV 캐시가 컨텍스트에 비례합니다.
   Gemma 4 는 기본 컨텍스트가 매우 길어 그냥 두면 KV 가 수 GB 를 먹습니다.
2. **뱅크 구축 후 `torch.cuda.empty_cache()`** — 파이프라인이 순차적이라
   PatchCore 구간과 모델 판독 구간이 겹치지 않습니다.
3. **`OLLAMA_KEEP_ALIVE=0`** — 호출 후 언로드. 느리지만 확실합니다.
4. **PatchCore 를 CPU 로** — 추론은 0.4GB 라 견딜 만하고, 뱅크 구축은
   어차피 수 분 걸리는 구간이라 시연 서사에 지장이 없습니다. VRAM 이
   통째로 비워집니다.

## 6. 아직 측정하지 않은 것

**여기 있는 수치는 전부 크기와 용량입니다. 성능이 아닙니다.**

| 재야 할 것 | 어떻게 |
|---|---|
| Gemma 4 12B 도구 호출이 실제로 되는가 | `scripts/check_models.py` |
| 40px 결함 크롭을 읽는가 (판별 1번) | VisA 크롭으로 Qwen3-VL-8B 와 A/B |
| 뱅크 패치가 결함인지 정상품인지 가르는가 (판별 5번) | 같은 방식 |
| 한국어 이슈 문장을 구조화하는가 | 인테이크 경로 |
| 실제 동시 VRAM 사용량 | `nvidia-smi` 로 관측 |

공개 벤치마크는 OCR·문서 이해 중심이라 **우리 과제를 대변하지 않습니다.**
1500px 제품 사진에서 40px 결함을 찾는 것은 문서 판독과 다릅니다.
**받아서 우리 크롭으로 재는 것이 유일한 답입니다.**

"벤치마크가 아니라 우리 과제로 모델을 골랐다"는 것 자체가 발표 재료가 됩니다.

## 7. 받아 둔 파일

4090 은 HuggingFace·ollama 레지스트리가 사내망에서 차단됩니다.
Mac 에서 받아 USB 로 옮깁니다.

```
~/Downloads/gemma4/
├─ gemma-4-12b-it-Q6_K.gguf            9.11 GB
├─ gemma-4-12b-mmproj-F32.gguf         0.19 GB
└─ gemma-4-26B-A4B-mmproj-F16.gguf     1.11 GB   ← 26B 는 이미 4090 에 있음
```

**mmproj 두 개는 원래 파일명이 둘 다 `mmproj-F16/F32.gguf` 라 그대로 받으면
서로 덮어씁니다.** 어느 모델용인지 알 수 있게 이름을 바꿔 저장했습니다.

### ollama 에 등록하는 법

`ollama pull` 이 아니라 로컬 파일로 만들어야 합니다. **mmproj 를 명시하지
않으면 또 텍스트 전용이 됩니다.**

`Modelfile` 을 만들고:

```
FROM ./gemma-4-12b-it-Q6_K.gguf
ADAPTER ./gemma-4-12b-mmproj-F32.gguf
PARAMETER num_ctx 8192
```

> `ADAPTER` 키워드는 ollama 버전에 따라 다를 수 있습니다. 최신 ollama 는
> mmproj 를 `FROM` 에 두 번째 인자로 받거나 자동 탐지하기도 합니다.
> 등록 후 **반드시 이미지를 한 장 넣어 답하는지 확인**하세요.
> 텍스트만 답하면 투영기가 안 붙은 것입니다.

```bash
ollama create gemma4-12b-vision -f Modelfile
ollama list
```

그다음 우리 설정에 물립니다.

```bash
set SHVO_LLM_PROVIDER=openai_compat
set SHVO_LLM_BASE_URL=http://localhost:11434/v1
set SHVO_LLM_MODEL=gemma4-12b-vision
set SHVO_VLM_PROVIDER=openai_compat
set SHVO_VLM_BASE_URL=http://localhost:11434/v1
set SHVO_VLM_MODEL=gemma4-12b-vision

python scripts/check_models.py
```

**LLM 과 VLM 에 같은 모델을 넣는 것이 이 구성의 요점입니다.**
