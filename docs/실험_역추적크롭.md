# 실험 기록 — 히트맵으로 짚어도 시각 언어 모델이 보는가

측정 2026-08-14 · RTX 4090 Laptop · CUDA · ollama 0.32.9 · `qwen3-14b` + `qwen3vl-8b`
재현 `python scripts/measure_trace_crop.py --max-normal 150 --defects 10`

아티팩트로만 남으면 git 이력에 안 남아 기획서 근거로 인용할 수 없어서
저장소로 옮긴 기록입니다.

---

## 1. 결론 — 판별 1번을 조건 없이 쓸 수 있다

정답 마스크 없이 **PatchCore 이상 점수만으로 결함 위치를 짚어 잘라도** 시각
언어 모델이 10장 중 9장을 맞혔습니다. **마스크로 자른 것(8/10)보다 낫습니다.**

VisA capsules · 정상 150장으로 뱅크 구성 · 결함 10장.

```
# 격자 56x56 · 원본 1500x1000 · 격자 한 칸 15x16px · 크롭 143x144

역추적 중심이 결함 위       8/10   ← 히트맵 정확도의 실제 값
역추적 크롭이 결함을 담음  10/10
역추적 크롭으로 defect 판정 9/10
마스크 크롭으로 defect 판정 8/10   ← 상한선
```

우려했던 시나리오는 일어나지 않았습니다. **"미검출 상황에서는 히트맵도 못
믿는 것 아닌가"** 가 걱정이었는데 아니었습니다. 미검출은 "점수가 임계값
아래"라는 뜻이지 "어디가 이상한지 모른다"가 아닙니다. 상대 순서는 유지되므로
최고 점수 패치는 여전히 결함 자리를 가리킵니다.

---

## 2. 판독을 좌우한 것은 모델이 아니라 크롭 크기였다

같은 모델·같은 좌표·같은 이미지에서 여유 픽셀만 바꿨습니다.

| 여유 | 크롭 크기 | 역추적 크롭 | 마스크 크롭 |
|---|---|---|---|
| 24px | 63×64 | **0/10** | 0/10 |
| 64px | 143×144 | **9/10** | 8/10 |

24px 에서는 **스무 건 전부 `unknown`** 이었습니다. 지어낸 것이 아니라 "무엇을
보는지 모르겠다"고 답한 것입니다. 격자 한 칸이 원본에서 15×16px 뿐이라 그것만
떼어 주면 제품의 어느 부위인지 알 수 없습니다.

`inspection/crop.py` 주석이 이것을 미리 적어 두었습니다 — *"한 칸만 떼어 보면
무엇을 보고 있는지 알기 어렵다. 주변 몇 칸을 함께 보여주면 '이게 제품의 어느
부위인가'가 드러나 판독이 정확해진다."*

### 같은 문제가 층을 바꿔 세 번 반복됐다

| 어디서 | 무엇이 묻혔나 | 해법 |
|---|---|---|
| PatchCore 입력 256/224 | 40px 결함이 격자 한 칸에 | 해상도 512/448 |
| 시각 언어 모델, 전체 1500px | 40px 결함이 화면에 | 의심 영역만 잘라 확대 |
| 시각 언어 모델, 63px 조각 | 맥락이 사라짐 | 여유를 64px 로 |

**셋 다 "모델에게 무엇을 얼마나 보여주는가"의 문제**이지 모델을 바꿔서 푸는
문제가 아니었습니다.

## 3. 정답 마스크보다 역추적이 나았다

```
002.JPG   역추적 defect  /  마스크 unknown
006.JPG   역추적 unknown /  마스크 normal
```

마스크 크롭은 결함 크기에 따라 박스가 달라집니다. 작은 결함이면 작은 박스가
되어 맥락이 부족해집니다. **역추적 크롭은 격자 한 칸 기준이라 항상 143×144 로
일정합니다.**

**고정 크기가 가변 크기보다 낫다** — 설계에 반영할 값어치가 있습니다.
판별 1·5번 모두 패치 좌표를 기준으로 일정한 크기를 잘라 주는 방식으로
통일하면 됩니다. `crop_with_context()` 가 이미 그 모양입니다.

---

## 4. 과장하면 안 되는 두 가지

**"결함을 담음 10/10" 을 히트맵 정확도로 말하면 안 됩니다.** 결함이 30~45px
인데 박스가 143px 이라 히트맵이 조금 빗나가도 담깁니다. 엄격한 지표는
**중심 적중 8/10** 쪽이고, 그것이 히트맵 정확도의 실제 값입니다.

**`006.JPG` 는 두 방식 모두 실패했습니다**(unknown / normal). 크롭을 어떻게
줘도 못 보는 것이 10장 중 1장 있습니다. 판별 1번을 단독 차단 조건으로 쓰면
그 1장에서 진단이 멈춥니다.

## 5. 도구 호출 — 통과

```
언어 모델
  [통과] 응답 · JSON 출력
  [통과] 도구 호출 — lookup_threshold({'line': 'line_02'})

시각 언어 모델
  [통과] 응답 · JSON 출력
```

**웹 데모를 도구 호출 경로로 바꾸는 작업의 전제가 확인됐습니다.**
`qwen3-14b`(8.4GB) 와 `qwen3vl-8b`(5.8GB) 를 동시에 설정해도 VRAM 16GB 에서
문제가 없었습니다.

이미지 판독 항목이 처음에는 "실패"로 나왔는데 **검사 기준이 잘못된 것**이었습니다.
정상 이미지에 `unknown` 을 냈다고 실패 처리했는데, 모델이 댄 근거는 *"체커보드
패턴이고 제품 표면이 아니다"* 로 맞는 말이었습니다. 같은 모델이 VisA 실데이터
에서는 9/10 을 냅니다. **쓸 수 있는 모델을 "쓰지 마라"고 판정하고 있었습니다.**

기준을 바꿨습니다 — **결함에 `normal` 을 내지 않고 정상에 `defect` 를 내지
않으면 통과**, `unknown` 은 실패가 아니라 **보류**로 따로 셉니다. 모를 때
지어내지 않는 것은 설계 의도이고, 그런 판정은 `usable=False` 로 빠져 사람에게
넘어갑니다.

## 6. VisA 300장 전 구간 — 완주, 다만 두 가지가 어긋난다

`demo_trace.py --contaminants 3 --max-normal 300`
뱅크 225장 + 홀드아웃 양품 75장 · 불량 12장.

```
깨끗한 뱅크   AUROC 0.941   판정: 임계값 조정으로 해결 불가
오염된 뱅크   AUROC 0.893   판정: 임계값 조정으로 해결 불가

질의 003.JPG  깨끗 2.8430 → 오염 2.8392  (0.1% 하락)
역추적        → 지목된 것이 원래 정상 이미지다. 오염이 아닐 수 있다.
```

### ① 스크립트 맺음말이 실제 결과와 반대였다 — 고침

출력 마지막에 *"스윕만 보면 두 경우 모두 '임계값을 다시 잡으면 된다'로
읽힌다"* 가 찍혔는데 **실제 판정은 두 경우 모두 "해결 불가"** 였습니다.
`CLAUDE.md` 는 정정됐는데 스크립트 안 문장만 옛 주장이 남아 시연 화면에
그대로 떴습니다.

**실제 판정을 읽어서 말하도록 고쳤습니다.** 문장을 고정해 두면 데이터가
바뀔 때 화면에 거짓이 뜹니다.

### ② 정상을 늘리면 오염 시연이 안 보인다

오염 3장 / 뱅크 225장 = **1.3%** 인데 점수가 0.1% 밖에 안 떨어졌고
**역추적이 오염 패치를 짚지 못했습니다.**

이건 조건을 바꿔 피할 문제가 아니라 **실제 한계**입니다. 대응은 아래 7장에
적었습니다.

### AUROC 는 홀드아웃 구성이 다르면 비교할 수 없다

정상 150장에서 0.998, 225장에서 0.941 인데 **홀드아웃이 25/25 와 75/12 로
다릅니다.** 양품이 3배라 과검 한 건의 무게가 다릅니다. 조건 없이 나란히
놓으면 "데이터를 늘렸더니 나빠졌다"로 읽히므로 `CLAUDE.md` 표에 조건 열을
붙였습니다.

## 7. 낮은 오염률에서 역추적이 약해지는 문제 — 대응

**조건을 나누는 것으로 덮지 않습니다.** 시연용 조건과 측정용 조건을 따로
두면 "시연에서만 잘 되는 것"이 되고, 심사에서 물으면 답이 궁색해집니다.

원인은 **한 장으로 판단했기 때문**입니다. 오염률 1.3% 에서 특정 미검출
이미지 하나의 최근접 패치가 오염원일 확률은 낮습니다. 우연에 맡긴 셈입니다.

**실제 코드는 이미 여러 건을 모아 봅니다.**

- `inspection/trace.py` 의 `bank_contribution()` — 미검출 건들이 어느 뱅크
  이미지를 반복해 지목하는지 셉니다
- `agents/curate.py` 의 `plan_curation()` — 그 반복 지목을 오염 후보의
  근거로 씁니다. 주석에 *"한 장의 우연이 아니라 반복이 근거"* 라고 적혀
  있습니다

**약한 것은 `demo_trace.py` 뿐입니다.** 시연 스크립트만 단일 이미지를 봅니다.
여러 미검출 건의 반복 지목으로 바꾸면 낮은 오염률에서도 신호가 모입니다.

그리고 **이 한계 자체를 기획서에 쓰는 편이 낫습니다.** "오염률이 낮으면 한
건으로는 못 짚는다, 그래서 여러 건을 모아 본다"는 것이 설계 근거가 됩니다.
숨기면 심사에서 파고들었을 때 무너집니다.

## 8. 아직 안 잰 것

**판별 5번**(뱅크 패치가 결함인가 진짜 정상품인가)이 남았습니다. 뱅크 오염과
정상 분포 중첩을 가르는 자리라 과제의 핵심입니다.

판별 1번과 같은 방식(패치 좌표로 고정 크기 크롭)이 통할 가능성이 크지만
확인이 필요합니다. 다만 **1번과 성격이 다릅니다.**

| | 판별 1번 | 판별 5번 |
|---|---|---|
| 무엇을 묻나 | 이 이미지에 결함이 있는가 | 이 패치가 결함인가 진짜 정상품인가 |
| 대상 | 결함으로 접수된 이미지 | **정상으로 등록되어 뱅크에 들어간** 이미지 |
| 함정 | — | "정상으로 등록됐다"는 전제가 답을 유도할 수 있음 |

`agents/vision.py` 의 `judge_bank_patch()` 프롬프트에 *"registered as normal
is not evidence that it is normal"* 을 넣어 둔 것이 그 대비입니다. 실제로
그것이 작동하는지가 이 실험에서 갈립니다.
