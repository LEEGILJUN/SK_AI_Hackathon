# 검사 AI 자율 운영 에이전트 — 작업 목록과 역할 분담

> 2026 SK AI 해커톤 · AI Solution 리그
> 본선 기간 2026.8.21(금) ~ 9.4(금) · 2주
> 기준 모델: PatchCore (현행 SVI base 모델과 동일)

---

## 0. 왜 PatchCore 기준인가

현행 SVI의 base 모델이 PatchCore이므로, 시연 모델을 동일하게 맞춰야 "우리 라인에 그대로 적용 가능한가"라는 질문에 답할 수 있다.

PatchCore는 정상 이미지의 패치를 메모리 뱅크에 담아두고 최근접 거리로 이상 점수를 산출한다. 이 구조 때문에 **미검출이 발생했을 때 해당 이미지가 뱅크의 어떤 정상 패치와 가까웠는지를 그대로 되짚을 수 있다.** 판단 근거가 모델 내부에 이미 존재하므로, 진단 에이전트가 추측이 아니라 추적으로 원인을 규명할 수 있다. 이것이 이번 과제의 기술적 토대다.

또한 PatchCore는 역전파 학습이 없어 뱅크 재구성이 수 분 내에 끝난다. 2주 일정에서 재학습 루프를 반복 실행하며 검증하기에 유리하다.

## 0-1. 개발 및 시연 환경

개발과 시연 모두 RTX 4090 노트북에서 수행한다. 현장에 그대로 들고 갈 수 있으므로 개발 환경과 시연 환경이 동일하며, 환경 차이로 인한 시연 사고 가능성이 없다. 별도의 클라우드 GPU는 필요하지 않다.

데이터는 전부 가상으로 생성하므로 사내망 연결이나 사내 데이터 반입이 일절 없다. 이 점이 보안 규정 대응을 단순하게 만든다.

언어 모델은 4090에서 구동 가능한 로컬 모델을 우선 검토한다. 로컬로 구동할 경우 폐쇄망 동작 가능성을 시연으로 직접 증명할 수 있다는 부수 효과가 있다. 다만 에이전트의 도구 호출 안정성이 확보되지 않으면 시연 중단 위험이 있으므로, 모델 호출 계층을 어댑터로 추상화해 로컬 모델과 외부 API를 설정으로 교체할 수 있게 구성한다.

## 1. 미검출 원인 분류 체계 (PatchCore 기준)

진단 에이전트가 가르는 다섯 가지 원인과 각각의 판별 방법이다. 이 표가 전체 과제의 설계 기준이 된다.

| 원인 | 판별 방법 | 조치 | 재학습 |
|---|---|---|---|
| 임계값 문제 | 이상 점수는 높은데 임계값 아래에 위치 | 임계값 재조정 | 불필요 |
| 뱅크 오염 | 최근접 정상 패치를 확인했더니 실제로는 결함 | 오염 샘플 제거 후 뱅크 재구성 | 필요 |
| 커버리지 부족 | 현재 조건의 정상 패치가 뱅크에 없음 | 해당 조건 정상 이미지 추가 | 필요 |
| 정상 분포 중첩 | 최근접 패치가 진짜 정상품이며 형상이 유사, 점수 분포가 정상과 겹침 | 판정 기준 재정의, 전용 판별 로직, 촬영 조건 개선 | 효과 없음 |
| 설비·광학 | 화질 지표가 기준 분포를 이탈 | 설비 점검 요청 | 차단 |
| 기준 문제 | 검출은 했으나 판정 기준상 양품으로 분류 | 판정 기준 재정의 요청 | 차단 |

여섯 중 넷은 뱅크를 다시 만드는 것이 답이 아니다. 불필요한 재학습을 막는 것 자체가 이 서비스의 가치이며, 진단 성능의 진짜 시험대는 "재학습을 해야 할 때 하는가"가 아니라 "하지 말아야 할 때 멈추는가"에 있다.

### 진단 판별 항목 (일곱 가지)

1. 결함이 이미지에 실제로 보이는가 — 시각 언어 모델 판독
2. 화질 지표가 기준 분포를 벗어났는가 — 밝기·대비·선예도·노이즈 통계 비교
3. 이상 점수가 임계값 대비 어느 위치인가 — 추론 결과 조회
4. 최근접 정상 패치가 무엇인가 — 메모리 뱅크 역추적
5. **그 패치가 결함인가 진짜 정상품인가** — 시각 언어 모델 판독 또는 사람 확인
6. 현재 조건의 정상 패치가 뱅크에 포함되어 있는가 — 뱅크 구성 이력 조회
7. 판정 기준상 불량이 맞는가 — 기준 테이블 대조

1번과 5번만 시각 언어 모델을 쓰고, 나머지는 조회와 계산으로 정확한 값을 얻는다. 진단의 신뢰도는 인상 판단이 아니라 이 정량 근거에서 나온다.

**4번과 5번이 함께 작동하는 지점이 진단의 핵심이다.** 최근접 패치를 찾아내는 것만으로는 부족하고, 그것이 잘못 들어간 결함인지 진짜 정상품인지를 구분해야 원인이 갈린다. 결함이면 뱅크 오염이고, 진짜 정상품이면 정상 분포 중첩이다. 조치가 정반대이므로 이 구분을 틀리면 진단 전체가 틀린다.

### 정상 분포 중첩이 특히 중요한 이유

PatchCore는 정상에서 얼마나 벗어났는지만 본다. 새로 결함으로 정의된 형상이 정상 변동 범위 안에 들어가 있으면 거리 기반으로는 원리적으로 구분되지 않는다. 이 경우 데이터를 더 넣어도 해결되지 않는다. 해당 결함을 뱅크에 넣으면 오히려 더 못 잡게 되고, 유사한 정상 패치를 제거하면 진짜 정상품에서 과검이 발생한다.

진단 에이전트는 **임계값을 낮춰가며 검출률과 과검률의 관계를 산출**하여 "이 결함을 잡으려면 과검률이 얼마가 된다"를 제시한다. 이로써 임계값 조정으로는 해결되지 않음을 정량적으로 증명하고, 판정 기준 재정의나 전용 판별 로직 추가, 촬영 조건 개선 같은 다른 층위의 조치를 권고한다. 현재는 담당자가 감으로 판단하는 영역이며, 해결되지 않을 재학습을 반복하는 것을 막아 준다는 점에서 실질적인 절감 효과가 있다.

## 2. 역할 분담

### 이길준 — LLM·에이전트·추론 환경

에이전트가 실제로 돌아가는 판을 만들고, 진단 판정 로직을 설계한다.

- 언어 모델·시각 언어 모델 실행 환경 구축 (온프레미스 실행 전제, 폐쇄망 대응 가능한 구조)
- 에이전트 오케스트레이션 계층 — 다섯 에이전트 간 판단 결과와 근거 전달 구조
- 도구 호출 인터페이스 설계 — 각 판별 항목을 에이전트가 호출할 수 있는 함수로 노출
- PatchCore 추론 파이프라인 구축 및 최근접 패치 역추적 기능 구현
- 진단 에이전트 판정 로직 — 여섯 판별 항목의 조합 규칙과 근거 리포트 형식
- 데모 환경 구축 및 시연 시나리오 실행 안정화
- 기획서·발표자료 총괄, 피칭

### 장영진 — 도메인·비전·시나리오·프로세스

무엇이 옳은 판정인지를 정의하고, 만들어진 것이 현업에서 말이 되는지 검증한다.

- 미검출 원인 분류 체계의 현업 타당성 검토 및 확정
- 시연 시나리오 20건 이상 설계 — 원인별 케이스와 **정답 라벨 확정**
- VisA 기반 결함 조작 설계 — 뱅크 오염 주입, 임계값 조작, 화질 열화 적용 규칙
- 화질 지표 정의와 기준 분포 산출 방식 결정
- 판정 기준 테이블 설계 — 픽셀 마스크 면적 기준 임계값 체계
- 진단 결과의 도메인 검증 — 에이전트 판정이 실제 판단과 일치하는지 채점
- 업무 프로세스 플랫폼화 설계 — 이슈 접수부터 승인까지의 흐름을 표준 절차로 정의
- 거버넌스 기록 스키마 — 무엇을 남겨야 조직 자산이 되는지 정의

### 이동현 — 데이터·가상공장

에이전트가 조회할 대상을 만든다. 진단의 근거가 되는 데이터 계층 전체를 담당한다.

- VisA 데이터셋 확보 및 가상 공장 스토리지 구성 (폴더트리 기반)
- 가상 라인 설계 — 3~4개 객체를 별개 라인으로 구성, 일자별 생산 데이터 분할
- 가상 MES 데이터 생성 — 로트, 설비 ID, 공정 조건, 시각, 검사 결과
- 재학습 프로젝트 폴더 구조 재현 — 현행 방식과 동일한 형태로 과거 이력 구성
- 학습 이력 인덱서 — 폴더 스캔으로 뱅크 구성 프로파일 복원, 버전 간 차이 비교
- 과거 이슈 이력 데이터 생성 및 이슈 이력 그래프 구축
- 결정론적 조회 계층 — 뱅크 구성, 화질 기준 분포, 임계값, 판정 기준 테이블과 조회 함수
- 그래프 검색 — 이슈 이력에 한정한 유사 사례 탐색

### 공동 작업

- 진단 에이전트 구현은 이길준과 장영진이 함께 진행한다. 판정 기준은 도메인이고 구현은 로직이므로 분리되지 않는다.
- 통합 테스트와 재현성 검증은 3인이 함께 수행한다.

## 4. 시연 시나리오 구성

VisA에서 성격이 다른 3~4개 객체를 각각 별개 라인으로 가정한다. 일자별로 데이터를 나누어 1~4일분으로 초기 뱅크를 구성하고, 5~7일분을 운영 데이터로 사용한다.

| 이슈 유형 | 정답 원인 | 데이터 구성 방법 | MVP |
|---|---|---|---|
| 미세 결함이 지속 미검출 | 임계값 | 임계값을 실제 결함 점수 분포보다 높게 설정 | 포함 |
| 특정 형상 결함만 계속 빠짐 | 뱅크 오염 | 정상 학습셋에 해당 결함 이미지 수 장을 혼입 | 포함 |
| 신규 로트에서 검출률 급감 | 커버리지 부족 | 특정 조건의 정상 이미지를 뱅크 구성에서 제외 | 포함 |
| 새로 결함으로 정의된 형상이 안 잡힘 | 정상 분포 중첩 | 정상과 시각적으로 가까운 결함 유형 선정, 점수 분포 중첩 확인 | 포함 |
| 어느 시점부터 전반적 성능 저하 | 설비·광학 | 해당 일자 이후 이미지에 블러·밝기 시프트 적용 | 포함 |
| 잡았는데 양품으로 흘러감 | 기준 문제 | 마스크 면적 기준 임계값을 변경 | 포함 |
| 타 라인에서 이미 해결된 건 | 중복 | 과거 이슈 이력에 동일 케이스를 사전 배치 | 포함 |
| 특정 장비 개체만의 이상 | 설비·광학 | 개체 단위 식별 정보 필요 — 이번 범위 제외 | 제외 |

각 유형마다 3건 이상을 배치해 20건 이상을 구성한다. 모든 케이스는 정답 원인이 사전에 확정되어 있으므로 진단 정확도를 실제로 측정할 수 있다.

**뱅크 오염 케이스가 가장 중요하다.** 정상 학습 데이터에 불량이 섞여 들어가면 그와 유사한 불량이 전부 정상으로 판정되는데, 사람이 원인을 찾으려면 상당한 시간이 걸린다. 최근접 패치를 역추적하면 즉시 규명되므로, 에이전트의 가치가 가장 선명하게 드러나는 시나리오다.

## 7. 저장소와 협업 규칙

**저장소: https://github.com/LEEGILJUN/SK_AI_Hackathon**

세 명이 각자 PC에서 작업하므로 데이터 구조와 코드를 저장소로 공유한다. 다만 무엇을 올리고 무엇을 올리지 않는지가 명확해야 저장소가 망가지지 않는다.

### 올리지 않는 것

| 대상 | 이유 | 대신 |
|---|---|---|
| VisA 원본 이미지 | 1만 장 수 GB, GitHub 파일당 100MB 제한에 걸린다 | 내려받아 폴더트리를 만드는 스크립트를 커밋 |
| 메모리 뱅크 파일 (.pt, .npz) | 바이너리이고 용량이 크다 | 스크립트로 수 분 내 재구성 |
| 실행 로그, 캐시, 중간 산출물 | 저장소 오염 | .gitignore 등록 |

Git LFS는 무료 할당량이 월 1GB 수준이라 세 명이 클론을 반복하면 금방 소진된다. 이미지를 올리지 않는 편이 단순하다.

**생성 스크립트 방식이 재현성 목표와도 맞는다.** 시드를 고정해 각자 실행하면 동일한 구조가 만들어지므로, "데이터를 공유했다"가 아니라 "누구나 같은 데이터를 만들 수 있다"가 된다. 5장의 재현성 100% 목표를 뒷받침하는 근거이기도 하다.

### 저장소 구조

```
SK_AI_Hackathon/
├─ README.md                  # 실행 방법, 데이터 출처와 라이선스 명시
├─ data/
│  ├─ build_factory.py        # VisA → 가상 공장 폴더트리 생성
│  ├─ manifest.csv            # 이미지 ↔ 라인/일자/로트 매핑
│  ├─ mes.csv                 # 가상 MES 데이터
│  ├─ scenarios.yaml          # 시나리오 20건 + 정답 원인
│  ├─ criteria.yaml           # 판정 기준 테이블 (마스크 면적 기준)
│  ├─ quality_baseline.yaml   # 화질 지표 기준 분포
│  └─ issue_history.jsonl     # 과거 이슈 이력
├─ inspect/                   # PatchCore 추론, 최근접 패치 역추적, 임계값 스윕
├─ agents/                    # 에이전트별 프롬프트와 판정 로직
├─ indexer/                   # 학습 이력 인덱서
├─ app/                       # 이슈 접수 웹 인터페이스
├─ scripts/                   # 뱅크 구성, 평가, 리포트 생성
└─ .gitignore                 # VisA 원본, 뱅크, 로그, 캐시 제외
```

### 파일 소유권

| 파일 | 소유 | 원칙 |
|---|---|---|
| `data/scenarios.yaml` | 장영진 | **정답 파일이다.** 진단 로직을 만드는 쪽이 정확도를 맞추려고 고치지 않는다. 변경이 필요하면 반드시 합의한다 |
| `data/criteria.yaml`, `quality_baseline.yaml` | 장영진 | 판정 기준의 단일 출처 |
| `data/build_factory.py`, `mes.csv`, `manifest.csv` | 이동현 | 데이터 생성의 단일 출처 |
| `agents/`, `inspect/` | 이길준 | 판정 로직과 추론 |

정답 파일을 고쳐 정확도를 맞추면 숫자 자체가 무의미해진다. 이 원칙만은 예외를 두지 않는다.

### 공개 범위

대회 기간 중에는 **비공개(private)로 유지한다.** 그라운드룰에 해커톤 정보의 무단 유출과 공유가 실격 사유로 명시되어 있고, 다른 팀이 우리 접근법을 그대로 볼 수 있는 상태를 굳이 만들 이유가 없다. 사무국이 Github 링크를 선택 첨부 항목으로 허용하고 있으므로, 제출 시점에 공개로 전환하거나 심사용 접근 권한을 부여하는 방식으로 결정한다.

### 라이선스 표기

README에 VisA의 출처와 CC BY 4.0 라이선스를 명시한다. 이미지를 재배포하지 않고 각자 내려받는 구조이므로 표기만으로 조건을 충족한다. 사용한 오픈소스 라이브러리의 라이선스도 함께 정리한다.

### 오프라인 동작 확인

개발 중 외부 API를 사용하더라도, 최종 통합 테스트는 **네트워크를 끊은 상태에서 한 번 수행한다.** 개발 과정에서 남은 외부 호출 경로가 결선 현장에서 문제를 일으키지 않도록 하기 위함이며, 동시에 폐쇄망 동작 가능성을 시연으로 직접 증명하는 근거가 된다.

## 8. 원칙

- **사내 데이터는 일절 사용하지 않는다.** 공정 조건, 장비 공급사, 생산 거점, 사내 결함 정의 체계 등 식별 가능한 정보는 기획서와 산출물 어디에도 넣지 않는다. 학습 이력 인덱서도 사내 폴더 구조를 전제하지 않고 일반적인 스캔 규칙으로 추상화한다.
- **무인 배포는 만들지 않는다.** 릴리즈 에이전트는 배포 패키지와 승인 요청 문서까지만 생성한다. 품질 검사 설비의 특성상 의도적으로 배제한 설계이며, 이 경계를 스스로 그은 것 자체가 설득력이 된다.
- **역추정 결과는 추정으로 표시한다.** 과거 이력 복원은 근거와 함께 추정임을 명시하고, 담당자가 확인한 경우에만 확정 이력으로 승격한다.
- **하나가 끝까지 도는 것이 여러 개가 반쯤 되는 것보다 낫다.** 범위 확대 압력이 생기면 뱅크 오염 시나리오 한 건의 완결된 루프를 우선한다. 뱅크 오염과 정상 분포 중첩은 반드시 함께 시연한다. 둘의 구분이 진단의 핵심이기 때문이다.
- 오픈소스 라이브러리와 공개 데이터셋은 라이선스와 출처를 명시한다. VisA는 CC BY 4.0(Amazon Science)이며, MVTec AD는 비상업 라이선스이므로 사용하지 않는다.
