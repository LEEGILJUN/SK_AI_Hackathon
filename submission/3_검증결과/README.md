# 3_검증결과

**심사가 묻는 것: 작동한다는 걸 어떻게 확인했나.**

## 1. 검증 방법

세 층으로 확인합니다.

| 층 | 무엇을 보는가 | 명령 |
|---|---|---|
| 자동 시험 | 규칙·배선·경계 조건 | `python -m pytest tests/ -q` |
| 형식 검사 | 시나리오·공장 데이터·문서·공개 가능 여부 | `python scripts/check_all.py` |
| 실측 | 실데이터에서 수치가 나오는가 | `scripts/measure_*.py` |

**실측은 공개 데이터(VisA)로 합니다.** 합성 데이터로 잰 값은 근거로 쓰지
않습니다. 이유는 5장에 있습니다.

### 자동 시험 485건

```
485건 수집 · 통과 483 · 건너뜀 2
```

숫자를 맞추는 시험이 아니라 **틀렸던 것을 다시 틀리지 않게 하는 시험**
입니다. 예를 들면 이런 것들입니다.

- 보충이 0장인데 재구성이 성공으로 끝나지 않는가
- 뱅크 구성을 바꿨는데 저장소가 옛 뱅크를 돌려주지 않는가
- 재구성이 답이 아닌 원인에서 뱅크를 건드리지 않는가
- 화면이 표시하는 크롭 좌표를 화면이 따로 계산하지 않는가

### 재현 절차

```bash
git clone https://github.com/LEEGILJUN/SK_AI_Hackathon.git
cd SK_AI_Hackathon
pip install -r requirements.txt
python -m pytest tests/ -q          # 시험. 모델도 GPU도 필요 없습니다
python scripts/check_all.py         # 형식 검사
python scripts/run_demo.py          # 전 구간 한 번
```

실측을 다시 하려면 VisA 원본(1.8GB, CC BY 4.0)이 필요합니다. 받는 곳과
배치 규약은 저장소 `docs/이어서작업.md` 1장에 있습니다.

**뱅크 재구성은 장치를 타지 않습니다.** 같은 시드로 세우면 뱅크 행수가
cuda 와 mps 에서 정확히 같습니다(4,704행). 재현성 검사가 이 위에 섭니다.

## 2. 검증 기록: 원인 진단

### 시나리오 24건 채점

정답 라벨이 걸린 시나리오 24건에 진단 규칙을 돌린 결과입니다.

```
원인 일치        22/24
재구성 여부 일치  22/24
금지 행위 위반    0건
```

**틀린 2건이 전부 같은 갈림입니다.** 임계값 문제와 정상 분포 중첩 사이이고,
이상 점수비만으로는 갈리지 않습니다(0.89와 0.95가 서로 다른 정답).
경계값 조정으로 풀 문제가 아니라고 판단해 두었습니다.

**정답 파일은 채점 기준이라 수정하지 않습니다.** 정확도가 낮게 나온다고
정답을 고치면 측정 자체가 무의미해집니다.

### 판별 5번 하나가 조치를 반대로 돌립니다

실모델 완주에서 확인했습니다. 같은 이미지, 같은 이상 점수인데 판별 5번의
값 하나로 이렇게 갈립니다.

| 판별 5번 | 원인 | 조치 | 뱅크 재구성 |
|---|---|---|---|
| 진짜 정상품 | 임계값 문제 | 임계값 재조정 | **금지** |
| 잘못 섞인 결함 | 뱅크 오염 | 혼입 제거 후 재구성 | **필요** |

## 3. 검증 기록: 왜 임계값 조정으로는 안 되는가

**이 서비스의 존재 이유에 대한 답입니다.**

VisA 실측에서 오염된 뱅크는 "임계값 조정으로 해결 불가"로 나왔습니다.

```
오염된 뱅크   AUROC 0.883 · 전건 검출에 필요한 과검률 59.5%
```

여기까지는 스윕이 잘 작동합니다. **문제는 정상 분포 중첩에서도 똑같이
"해결 불가"가 나온다는 것입니다.** 두 원인은 조치가 정반대인데(오염은 제거
후 재구성, 중첩은 재구성 금지) 스윕은 그 갈림을 만들지 못합니다.

**그 갈림을 만드는 것이 역추적입니다.** 그래서 진단이 역추적을 임계값보다
먼저 봅니다.

### 임계값은 품목마다 다릅니다

12개 품목에서 과검 1% 지점의 임계값을 측정했습니다.

| 품목 | 과검 1% 임계값 | 그때 검출 | AUROC |
|---|---|---|---|
| candle | 1.925 | 66/100 | 0.971 |
| capsules | 2.560 | 50/100 | 0.926 |
| pcb1 | 2.206 | 90/100 | 0.993 |
| pcb4 | 2.245 | 95/100 | 0.996 |
| pipe_fryum | 1.983 | 95/100 | 0.997 |

전 품목 값은 `데이터_품목별임계값.json` 에 있습니다.

**어느 품목도 완전히 갈리지 않습니다.** 정상 최대와 결함 최소가 12품목
전부 겹칩니다. 임계값을 어디에 둬도 미검이나 과검 중 하나는 남습니다.

## 4. 검증 기록: 뱅크와 데이터

### 해상도가 모자라면 데이터를 늘려도 신호가 없습니다

| 설정 | AUROC |
|---|---|
| 256/224, 정상 60장 | 0.526 (무작위 수준) |
| 512/448, 정상 60장 | 0.931 |
| 256/224, 정상 150장 | 0.502 |
| 512/448, 정상 150장 | 0.998 |

VisA 결함이 원본에서 40×40px 라 256 격자에서는 한 칸에 묻히고 이웃 평균에
희석됩니다. **입력 해상도 512는 이 측정으로 정해진 값입니다.**

위 네 줄은 전처리에 중앙 크롭이 있던 시절의 값입니다. 지금은 크롭 없이
512 정사각으로 넣습니다. **해상도가 가르는 폭이 이만큼이라는 것**을 보이는
표이고, 절대값을 지금 시스템의 값으로 읽지 마십시오.

### 같은 보드의 앞뒤면이 완전히 갈립니다

pcb1(앞면) 뱅크로 재면 pcb2(뒷면) 정상이 pcb1 **결함보다 높게** 찍힙니다
(AUROC 1.000, 겹침 없음). **품목마다 뱅크가 따로여야 하는 이유**이고,
뒤집으면 뱅크를 잘못 물 때 전 건이 불량으로 뜹니다.

### coreset 이 집는 것은 결함이 아닙니다

혼입 이미지가 뱅크에 남기는 패치를 세어 봤습니다.

| 혼입률 | 그 이미지 출신 패치가 뱅크에서 | 결함 **위** 패치가 뱅크에서 |
|---|---|---|
| 3.2% | 14.2% (4.4배) | **0.3%** (16/6,349) |
| 11.8% | 31.1% (2.6배) | **1.6%** (112/6,963) |

혼입 이미지 출신이 4.4배로 부풀어도 **결함 그 자체는 0.3%** 입니다.
coreset 이 집는 것은 결함이 아니라 결함이 있는 이미지의 멀쩡한 표면입니다.
실측에서 그 887개 중 871개(98.2%)가 정상부였습니다.

**이 수치가 판별 5번의 한계도 설명합니다.** 역추적이 혼입 이미지를 정확히
지목해도 그 패치 자리는 대개 멀쩡한 부분이라, 시각 언어 모델이 "진짜
정상품"이라 답하는 것이 틀린 게 아닙니다.

## 5. 합성 데이터를 근거로 쓰지 않는 이유

합성 데이터에서 나온 결과가 실데이터에서 네 번 반증됐습니다.

| 합성에서 | 실데이터(VisA)에서 |
|---|---|
| 오염된 뱅크도 AUROC 1.000, "해결 가능" | AUROC 0.883, "해결 불가" |
| coreset 증폭 50~70% | 결함 위 패치는 0.3~1.6% |
| 고립도가 혼입을 못 짚음 | pcb1 에서 정밀도 100% |
| 판별 2번이 결함을 화질 이탈로 읽음 | 재현되지 않음 |

합성 결함은 뚜렷해서 정상 분포에서 멀리 떨어져 있고, VisA 결함은 미세해서
그렇게 튀지 않습니다. **그래서 이 문서의 수치는 전부 VisA 실측입니다.**

## 6. 알려진 한계

숨기지 않고 적습니다. 심사에서 확인하실 수 있어야 합니다.

### 판별 1번이 위치를 잘 못 짚습니다

결함이 이미지에 실제로 보이는지를 시각 언어 모델이 판독하는 항목입니다.
**모델의 문제가 아니라 위치의 문제**임을 실측으로 좁혔습니다.

```
정답 마스크로 자른 조각 (12품목)      80.8%
자리를 놓쳤을 때 (대조군)             11.0%
역추적 상위 1자리로 자른 조각 (pcb1)   3/10
```

**7.4배 갈리므로** "확대된 조각이면 결함이라 한다"가 아닙니다. 자리를
정확히 주면 판독은 됩니다. 역추적이 그 자리를 짚는 정확도가 남은 문제입니다.

### 판별 7번 면적이 아직 상수에 가깝습니다

면적을 뱅크별 자리 기준선 대비로 재도록 바꿨으나, 기준선이 없을 때의 옛
방식은 화면의 99.9%가 나옵니다. 화면에 어느 기준으로 쟀는지 함께 표시하고,
기준선이 없으면 "판정 기준과 대조할 수 없는 값"이라고 적습니다.

### 측정 조건이 바뀐 값

전처리에서 중앙 크롭을 뺀 뒤 일부 수치는 다시 재야 합니다. 이 문서의 표에는
측정 조건을 함께 적었고, **조건이 다른 값을 나란히 놓고 비교하지 않습니다.**
