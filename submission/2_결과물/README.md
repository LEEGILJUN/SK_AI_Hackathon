# 2_결과물

**심사가 묻는 것: 기획서에서 정의한 핵심 기능이 실제로 작동하는가.**

## 1. 작동하는 앱 URL

```
주소      (배포 후 채웁니다)
아이디    (배포 후 채웁니다)
비밀번호  (배포 후 채웁니다)
```

**로그인을 건 이유.** 이 앱은 모델 API 키가 연결돼 있고 GPU 추론이 도는
기계에서 실행됩니다. 주소를 아는 누구나 누르면 계정에서 토큰이 나가고 시연
중에 느려집니다. 위 계정은 심사용이며 다른 곳에 쓰지 않습니다.

브라우저에서 그대로 열립니다. 설치할 것이 없습니다.

## 2. 3분 안에 확인하는 법

### 순서

1. 주소를 열고 로그인합니다.
2. 화면에 이슈 입력창 하나가 있습니다. **예시 문장이 미리 들어 있습니다.**
   그대로 두거나 직접 쓰셔도 됩니다.
3. 실행을 누릅니다. 열 단계가 차례로 채워집니다.
4. 화면 위쪽에 **누가 도구 순서를 정했는지**가 표시됩니다.

### 무엇을 보시면 되는가

| 보실 것 | 어디에 | 왜 |
|---|---|---|
| 도구 호출 기록 | 화면 상단 | 열 단계가 전부 도구이고, 순서를 언어 모델이 정합니다 |
| 진단 근거 | 5단계 | 히트맵, 이상 점수, 역추적한 두 자리의 크롭이 나란히 놓입니다 |
| 조회 방식 표시 | 조회 목록 | 어느 조회가 조인이고 어느 것이 그래프 검색인지 붙어 있습니다 |
| 신구 비교 | 9단계 | 새 뱅크를 판정에 쓰지 않고 병렬로만 돌려 갈린 건만 뽑습니다 |
| 승인 요청에서 멈춤 | 10단계 | 배포하지 않습니다. 사람이 승인합니다 |

### 라인을 바꿔 보시면 다른 것이 나옵니다

라인마다 다른 원인이 심겨 있습니다. **재구성이 답이 아닌 라인에서는
6단계에서 멈추고 왜 멈췄는지가 적힙니다.** 그것이 이 서비스의 주장입니다.

| 라인 | 나오는 원인 | 조치 |
|---|---|---|
| 뱅크 오염 라인 | 뱅크 오염 | 혼입 이미지 제거 후 재구성, 열 단계 완주 |
| 커버리지 부족 라인 | 커버리지 부족 | 조건별 정상 이미지 보충 후 재구성 |
| 깨끗한 라인 | 임계값 문제 등 | **재구성하지 않고 멈춤** |

(라인별 구성은 4090 검증 후 확정해 표를 채웁니다.)

### 판별 5번을 바꿔 보시면 조치가 반대로 갑니다

화면에 판별 5번(최근접 뱅크 패치가 결함인가 진짜 정상품인가)을 지정하는
칸이 있습니다. **같은 이미지, 같은 점수인데 이 값 하나로 원인과 조치가
정반대로 갑니다.**

- `결함` → 뱅크 오염 → 제거 후 재구성
- `진짜 정상품` → 임계값 문제 또는 정상 분포 중첩 → **재구성 금지**

지정한 값은 화면에 "시연을 위해 지정한 값"이라고 그대로 표시됩니다.

### 멈추는 것도 결과입니다

정보가 부족하면 되묻고, 이미 해결된 사례면 중복으로 끊고, 배포된 뱅크가
없는 품목이면 2단계에서 멈춥니다. **미도달 단계는 회색으로 남고 왜 멈췄는지가
적힙니다.** 설계대로입니다.

## 3. 결과물 본체

### 저장소

```
https://github.com/LEEGILJUN/SK_AI_Hackathon
```

### 직접 실행하는 법

```bash
git clone https://github.com/LEEGILJUN/SK_AI_Hackathon.git
cd SK_AI_Hackathon
pip install -r requirements.txt

python -m uvicorn app.main:app --port 8000     # 웹 화면
python scripts/run_demo.py                      # 전 구간 한 번, 터미널에서
```

**모델 없이도 돕니다.** 언어 모델이 연결되지 않으면 같은 도구들을 고정
순서로 실행하고, 화면에 "순서를 모델이 정한 것이 아닙니다"라고 표시합니다.
모델을 붙이려면 이렇게 합니다.

```bash
export SHVO_LLM_PROVIDER=anthropic
export SHVO_VLM_PROVIDER=anthropic
export ANTHROPIC_API_KEY=<키>
python scripts/check_models.py     # 응답·JSON·도구 호출·이미지 판독을 실제로 시켜 봅니다
```

로컬 모델도 같은 자리에 붙습니다(`SHVO_LLM_PROVIDER=openai_compat`).
**어댑터 계층 하나만 갈아끼우고 에이전트 코드는 고치지 않습니다.**

### 구성

| 경로 | 하는 일 |
|---|---|
| `app/` | 웹 화면과 파이프라인 |
| `agents/` | 다섯 에이전트. 접수·진단·데이터 선별·학습 평가·릴리즈 |
| `agents/tools.py` | 도구 호출 계층. 열 단계가 전부 여기의 도구입니다 |
| `agents/adapters/` | 언어 모델·시각 언어 모델 어댑터. 설정으로 교체 |
| `inspection/` | PatchCore 추론, 역추적, 임계값 스윕, 화질 지표, 신구 비교 |
| `lookup/` | 조회 계층. 실구현을 끼우는 접합부 |
| `scheduler/` | 예약 실행 |
| `data/` | 시나리오 정답, 판정 기준, 가상 공장 생성기 |

## 4. 기획서의 핵심 기능과 어떻게 대응되는가

| 기획서에서 정의한 것 | 어디서 작동하는가 |
|---|---|
| 이슈 접수와 중복 차단 | 1단계. 자연어에서 라인·품목·제품명을 뽑고, 정보가 부족하면 되묻습니다 |
| 생산 정보 조회 | 2단계. 제품명·로트로 이미지를 찾고 그 품목의 뱅크를 확인합니다 |
| 재검사 | 3단계. 그 품목 뱅크로 추론해 미검·과검을 가려냅니다 |
| 판별 7항목 | 4단계. 전부 실제로 산출합니다 |
| 원인 진단 6종 | 5단계. 판정은 규칙이 내고 서술만 언어 모델이 합니다 |
| 데이터 선별 | 6단계. 무엇을 넣고 뺄지. **재구성이 답이 아니면 여기서 멈춥니다** |
| 뱅크 재구성 | 7단계. 계획이 뱅크를 건드리지 않기로 했으면 실행되지 않습니다 |
| 성능 검증 | 8단계. 검출률·과검률·AUROC와 재현성 |
| 신구 비교 | 9단계. 판정이 갈린 건만 사람에게 넘깁니다 |
| 승인 요청 | 10단계. 배포 패키지와 승인 문서까지. **배포 함수가 없습니다** |
