# 2_결과물

**심사가 묻는 것: 기획서에서 정의한 핵심 기능이 실제로 작동하는가.**

## 1. 작동하는 앱 URL

```
주소      (배포 후 채웁니다)
아이디    (배포 후 채웁니다)
비밀번호  (배포 후 채웁니다)
```

**로그인을 건 이유.** 이 앱은 모델 API 키가 연결돼 있고 GPU 추론이 도는
기계에서 실행됩니다. 주소를 아는 누구나 누르면 계정에서 토큰이 나가고 시연
중에 느려집니다. 위 계정은 심사용이며 다른 곳에 쓰지 않습니다.

브라우저에서 그대로 열립니다. 설치할 것이 없습니다.

## 2. 4분 시연 각본

화면에 입력 칸이 셋뿐입니다. **이슈 원문 하나가 주 입력이고**, 나머지 둘은
시연에서 값을 바꿔 보시라고 열어 둔 것입니다.

```
현장에서 올라온 이슈    자유 문장. 라인·품목·제품명을 언어 모델이 여기서 뽑습니다
시연 조정 · 판별 5번    최근접 뱅크 패치가 결함인가 진짜 정상품인가
판정 임계값            비우면 그 품목에 걸린 값
```

**한 번 시작하면 중단할 수 없습니다.** 열 단계가 끝까지 실행되고 그동안
화면이 기다립니다. 화면에도 그렇게 적혀 있습니다.

### 장면 1. 뱅크 오염 — 끝까지 도는 것 (2분)

1. 이슈 칸에 들어 있는 예시 문장을 그대로 둡니다.
2. 판별 5번을 **`결함이다 → 뱅크 오염`** 으로 둡니다.
3. 실행합니다.

보실 것은 넷입니다.

| 무엇 | 어디에 |
|---|---|
| 도구 호출 기록과 **누가 순서를 정했는지** | 화면 위쪽 |
| 이 라인에 무엇이 심겨 있는지 | 2단계 「이 라인의 시연 구성」 |
| 진단 근거 — 히트맵·이상 점수·역추적한 두 자리의 크롭 | 5단계 |
| 사람이 확인할 것이 몇 장으로 줄었는지 | 9단계 신구 비교 |

**10단계에서 멈춥니다.** 배포 패키지와 승인 요청 문서까지만 만들고 장비에
반영하지 않습니다. 저장소에 배포 함수가 없습니다.

### 장면 2. 같은 화면, 판별 5번만 바꿔서 (1분)

같은 이슈를 그대로 두고 판별 5번만 **`진짜 정상품이다`** 로 바꿔 다시
실행합니다.

**같은 이미지, 같은 이상 점수인데 원인과 조치가 정반대로 갑니다.**

| 판별 5번 | 원인 | 조치 |
|---|---|---|
| 결함이다 | 뱅크 오염 | 혼입 제거 후 재구성 |
| 진짜 정상품이다 | 임계값 문제 또는 정상 분포 중첩 | **재구성하지 않음** |

이 갈림이 이 서비스의 핵심입니다. 최근접 패치를 찾는 것만으로는 부족하고,
그것이 잘못 들어간 결함인지 진짜 정상품인지를 갈라야 조치가 정해집니다.

지정한 값은 화면에 **"시연을 위해 지정한 값"** 이라고 그대로 표시됩니다.
숨기지 않습니다.

### 장면 3. 재구성이 답이 아닌 라인 (1분)

깨끗한 라인의 이슈를 넣습니다. 예를 들면 이렇게 씁니다.

```
3라인 기판이 검사에서 계속 양품으로 나옵니다. 제품 (그 라인의 제품명) 건입니다.
```

**6단계에서 멈추고 왜 멈췄는지가 적힙니다.**

> 뱅크를 건드리지 않는다: 원인이 임계값 문제이므로 뱅크 재구성은 답이
> 아니다. 데이터를 더 넣거나 빼도 해결되지 않으며, 오히려 정상 패치를
> 잘못 제거하면 과검이 늘어난다.

**미도달 단계는 회색으로 남습니다.** 실패가 아니라 설계입니다. 미검출
원인 여섯 중 넷은 재구성이 답이 아니고, 채점 시나리오 24건 중 16건이
여기 해당합니다.

### 장면 4. 커버리지 부족 — 보충하고 재구성 (선택)

조건이 비어 있는 라인의 이슈를 넣으면 다른 조치가 나옵니다.

```
5단계   커버리지 부족 — 그 조건의 정상 패치가 뱅크에 없다
6단계   보충 조건 N개
7단계   뱅크 재구성 — 보충 M장
```

**어느 조건이 비었는지를 문장이 아니라 값으로 넘깁니다.** 그래서 다음
단계가 그 조건의 이미지를 실제로 찾아옵니다.

### 직접 써 보셔도 됩니다

자유 문장을 넣으시면 **멈추는 것도 보실 수 있습니다.** 전부 설계된 동작
입니다.

| 넣으시면 | 화면이 |
|---|---|
| 제품명 없이 | 되묻습니다. 추측으로 채우지 않습니다 |
| 배포된 뱅크가 없는 품목 | 2단계에서 멈춥니다 |
| 이미 해결된 것과 같은 라인·품목·결함유형 | 중복으로 끊습니다 |
| 판별 5번을 `모델에게 묻기` 로 | 모델이 답하고, 못 하면 판정을 보류합니다 |

**어느 라인에 무엇이 심겨 있는지는 2단계 화면이 그대로 적습니다.** 표를
따로 보지 않으셔도 됩니다.

## 3. 결과물 본체

### 저장소

```
https://github.com/LEEGILJUN/SK_AI_Hackathon
```

### 직접 실행하는 법

```bash
git clone https://github.com/LEEGILJUN/SK_AI_Hackathon.git
cd SK_AI_Hackathon
pip install -r requirements.txt

python -m uvicorn app.main:app --port 8000     # 웹 화면
python scripts/run_demo.py                      # 전 구간 한 번, 터미널에서
```

**모델 없이도 돕니다.** 언어 모델이 연결되지 않으면 같은 도구들을 고정
순서로 실행하고, 화면에 "순서를 모델이 정한 것이 아닙니다"라고 표시합니다.
모델을 붙이려면 이렇게 합니다.

```bash
export SHVO_LLM_PROVIDER=anthropic
export SHVO_VLM_PROVIDER=anthropic
export ANTHROPIC_API_KEY=<키>
python scripts/check_models.py     # 응답·JSON·도구 호출·이미지 판독을 실제로 시켜 봅니다
```

로컬 모델도 같은 자리에 붙습니다(`SHVO_LLM_PROVIDER=openai_compat`).
**어댑터 계층 하나만 갈아끼우고 에이전트 코드는 고치지 않습니다.**

### 구성

| 경로 | 하는 일 |
|---|---|
| `app/` | 웹 화면과 파이프라인 |
| `agents/` | 다섯 에이전트. 접수·진단·데이터 선별·학습 평가·릴리즈 |
| `agents/tools.py` | 도구 호출 계층. 열 단계가 전부 여기의 도구입니다 |
| `agents/adapters/` | 언어 모델·시각 언어 모델 어댑터. 설정으로 교체 |
| `inspection/` | PatchCore 추론, 역추적, 임계값 스윕, 화질 지표, 신구 비교 |
| `lookup/` | 조회 계층. 실구현을 끼우는 접합부 |
| `scheduler/` | 예약 실행 |
| `data/` | 시나리오 정답, 판정 기준, 가상 공장 생성기 |

## 4. 기획서의 핵심 기능과 어떻게 대응되는가

| 기획서에서 정의한 것 | 어디서 작동하는가 |
|---|---|
| 이슈 접수와 중복 차단 | 1단계. 자연어에서 라인·품목·제품명을 뽑고, 정보가 부족하면 되묻습니다 |
| 생산 정보 조회 | 2단계. 제품명·로트로 이미지를 찾고 그 품목의 뱅크를 확인합니다 |
| 재검사 | 3단계. 그 품목 뱅크로 추론해 미검·과검을 가려냅니다 |
| 판별 7항목 | 4단계. 전부 실제로 산출합니다 |
| 원인 진단 6종 | 5단계. 판정은 규칙이 내고 서술만 언어 모델이 합니다 |
| 데이터 선별 | 6단계. 무엇을 넣고 뺄지. **재구성이 답이 아니면 여기서 멈춥니다** |
| 뱅크 재구성 | 7단계. 계획이 뱅크를 건드리지 않기로 했으면 실행되지 않습니다 |
| 성능 검증 | 8단계. 검출률·과검률·AUROC와 재현성 |
| 신구 비교 | 9단계. 판정이 갈린 건만 사람에게 넘깁니다 |
| 승인 요청 | 10단계. 배포 패키지와 승인 문서까지. **배포 함수가 없습니다** |
