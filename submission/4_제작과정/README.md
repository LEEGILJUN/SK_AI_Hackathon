# 4_제작과정

**심사가 묻는 것: 계획대로 진행했고, 막힌 지점을 어떻게 풀었나.**

## 1. 개발 일지

[`개발일지.md`](개발일지.md) 에 있습니다. **손으로 쓴 것이 아니라 작업할
때 남긴 커밋 기록을 그대로 옮긴 것**입니다.

```bash
python scripts/build_devlog.py
```

저장소에서 이 명령을 다시 돌리면 같은 내용이 나옵니다. 날짜도 커밋 날짜
그대로입니다. **기억으로 복원한 것이 아니라는 것을 확인하실 수 있습니다.**

이 저장소는 커밋 메시지에 무엇이 틀렸고 왜 그렇게 고쳤는지를 적어 왔습니다.
아래 3장의 "막힌 지점"은 그 기록에서 뽑은 것입니다.

## 2. WBS와 역할 분담

세 명이 겹치지 않게 나눴습니다.

| 담당 | 맡은 것 |

(회의록은 팀 기록에서 옮겨 붙입니다.)

## 3. 막힌 지점과 해결 과정

### 3.1 조용히 성공하는 답이 가장 오래 걸렸습니다

**이 프로젝트에서 제일 자주 부딪힌 종류입니다.** 오류가 나면 그 자리에서
알지만, 정상 응답으로 틀리면 며칠 뒤에 발견합니다.

| 무엇이 | 어떻게 보였나 | 실제로는 |
|---|---|---|
| 보충 경로 | 재구성 성공, 화면도 성공 | 0장 보충. 뱅크가 그대로 |
| 뱅크 저장소 | 뱅크를 새로 세운 것처럼 | 어제 구성으로 세운 옛 뱅크를 실었음 |
| 로트 조회 | "미검 없음" | 상한 50에 잘려 결함이 먼저 사라짐 |
| 보충 대상 | 정상 이미지 보충 | 미검 결함 6장을 정상으로 세어 뱅크에 넣음 |

**고친 방식이 같습니다.** 숫자가 실제로 움직였는지를 시험이 보게 했습니다.
"성공했다"가 아니라 "뱅크 장수가 몇에서 몇으로 갔다"를 단언합니다.

### 3.2 합성 데이터가 실데이터에서 네 번 반증됐습니다

초기에 합성 이미지로 빠르게 만들고 수치를 냈습니다. VisA 로 옮기자 결론이
뒤집혔습니다.

```
합성: 오염된 뱅크도 임계값 조정으로 해결 가능    AUROC 1.000
VisA: 해결 불가                                 AUROC 0.883, 과검 59.5%
```

합성 결함이 지나치게 뚜렷해 상대 순서가 유지된 탓입니다. **네 번 겪은 뒤
규칙을 세웠습니다.** 합성 수치는 근거로 쓰지 않고, 실측 표에는 측정 조건을
반드시 함께 적습니다.

### 3.3 판별 1번의 병목을 실측으로 좁혔습니다

시각 언어 모델이 결함을 못 본다는 문제였습니다. 세 가지 가설을 세우고
차례로 쟀습니다.

| 가설 | 결과 |
|---|---|
| 결함이 작아서 | **죽었습니다.** 가장 작은 결함 7/10, 가장 큰 결함 0/10 |
| 프롬프트 문제 | **거의 안 움직입니다.** 품목별 어휘를 줘도 +5%p, 과검이 함께 늘어남 |
| 위치를 못 짚어서 | **이것입니다.** 마스크로 자르면 80.8%, 자리를 놓치면 11% |

**7.4배 갈립니다.** 남은 것은 역추적 위치 하나로 좁혔고, 자리별 기준선
빼기를 시도했으나 상위 5자리에서도 5/10이 천장이라 그 방향은 접었습니다.
접은 것도 기록으로 남겼습니다.

### 3.4 실모델 전 구간 완주는 다섯 번째에 됐습니다

4090 노트북에서 로컬 모델로 도구 10개를 전부 부르게 하는 데 네 번 실패
했습니다. 마지막에 걸린 것은 대화 표현이었습니다.

**도구만 부른 턴의 내용이 빈 문자열이라, 서버가 보는 대화가 이렇게 됐습니다.**

```
assistant  ""                    무엇을 불렀는지 없음
tool       {"ok":true, ...}      무엇에 대한 답인지 모름
```

모델 입장에서는 "아직 아무것도 안 불렀는데 결과가 왔다"이므로 처음부터
다시 첫 도구를 불렀습니다. 같은 도구를 세 번 부르고 멈춘 원인이 이것이고,
어느 도구를 불렀는지를 그 턴에 함께 실어 해결했습니다.

```
결과: 도구 10개 완주 · 151초 · 최대 VRAM 13,567 MiB · 순서를 모델이 결정
```

### 3.5 맥에서 통과한 것이 증거가 되지 못했습니다

시연은 윈도우에서 돌고 시험은 맥에서 돕니다. 경로를 문자열로 견주는 자리
에서 **맥에서는 통과하고 시연 장비에서만 틀리는** 문제를 두 번 겪었습니다.
승인 문서가 사용자 경로를 못 걸렀고, 뱅크에서 뺄 이미지 표시가 4090 화면
에만 하나도 안 붙었습니다.

파이썬 버전도 같은 구조였습니다. 시연 장비가 3.11인데 3.12 문법을 쓰면
맥에서는 돌고 거기서만 죽습니다. 그 장비는 저장소가 막혀 있어 환경을
되돌릴 수 없으므로 **코드가 3.11에 맞춥니다.**

### 3.6 노트북이 세 번 블루스크린을 냈습니다

측정 도중 기계가 죽었습니다. 처음에는 뱅크가 커서 메모리가 터진 것으로
짐작했는데, 윈도우 이벤트 로그를 읽어 보니 아니었습니다.

```
0x0000013a  KERNEL_MODE_HEAP_CORRUPTION
0x0000003b  SYSTEM_SERVICE_EXCEPTION   (실패 주소 끝자리가 두 번 같음)
```

세 번 다 **화면 캡처를 자동화할 때**였고, 우리 스크립트로는 정상 완주
했습니다(정상 670장 × 12품목이 26분). 화면 캡처를 가로채는 보안 드라이버가
짚였고, 그 기계에서 캡처 자동화를 하지 않는 것으로 정리했습니다.

**짐작을 로그로 반증한 자리**라 남깁니다.

### 3.7 세션 셋이 같은 파일을 다른 방향으로 고쳤습니다

맥과 4090에서 동시에 작업하다 같은 파일을 서로 다른 구조로 고쳤습니다.
한쪽은 4라인에 라인별 원인을, 다른 쪽은 12라인에 대규모 뱅크를 넣었습니다.

**해결 방식을 규칙으로 만들었습니다.** 방향을 하나로 정하고, 부딪히는
자리는 이기는 쪽을 표로 적고, 버그 수정처럼 부딪히지 않는 것은 살릴 목록에
따로 적어 문서로 넘겼습니다. 그 문서가 저장소에 남아 있습니다.
