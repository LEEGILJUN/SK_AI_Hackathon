# 검사 AI 자율 운영 에이전트

**못 잡는 불량을 스스로 학습해 배포까지 준비하는 Self-Healing Vision Ops**

2026 SK AI 해커톤 · AI Solution 리그

---

## 이게 무엇인가

제조 현장에 배포된 AI 외관검사 모델이 "못 잡는 불량"을 만났을 때, 원인 진단부터 데이터 선별, 뱅크 재구성, 성능 검증, 배포 패키지 생성까지를 에이전트가 스스로 수행합니다.

검사 모델을 새로 만드는 프로젝트가 아니라, **이미 배포된 모델을 계속 살아 있게 유지하는 운영의 문제**를 다룹니다.

기준 모델은 PatchCore입니다. 정상 패치를 메모리 뱅크에 담아두고 최근접 거리로 판정하는 구조라, 미검출이 발생했을 때 그 이미지가 어떤 정상 패치와 가까웠는지를 되짚을 수 있습니다. 진단 에이전트는 이 경로를 따라가 원인을 규명합니다.

## 모델에 무엇이 들어가는가

**언어 모델과 시각 언어 모델이 읽는 것은 다섯 군데뿐입니다.** 나머지는 전부
조회와 계산입니다. 이 비중이 뒤집히면 진단이 인상 평가가 됩니다.

| 입력 데이터 | 어디에 쓰이는가 | 무엇이 읽는가 | 지금 상태 |
|---|---|---|---|
| 이슈 접수 텍스트 (메일·양식) | 라인·품목·결함유형·기간 추출 | LLM | 시나리오 24건 |
| 이슈 이미지 | 판별 1 — 결함이 실제로 보이는가 | VLM | 됨. **기판에서 위치 추정이 3/10** |
| 최근접 패치 잘라낸 것 | 판별 5 — 그 패치가 결함인가 정상품인가 | VLM | 됨 |
| 진단 근거 묶음 | 리포트 서술 (**판정은 규칙**) | LLM | 됨 |
| 도구 명세와 관측 결과 | 다음에 어떤 도구를 부를지 | LLM | **실모델로 열 단계 완주** |

**판별 1번과 5번만 시각 언어 모델을 씁니다.** 그리고 5번이 원인을 가릅니다 —
결함이면 뱅크 오염, 진짜 정상품이면 정상 분포 중첩이며 조치가 정반대입니다.

### 모델에 넣지 않는 것

정확한 값이 필요한 것은 조회와 집계로 답합니다. **임베딩하면 오히려 정확도가
떨어집니다.**

| 데이터 | 어떻게 답하는가 | 지금 상태 |
|---|---|---|
| 뱅크 구성 프로파일, 화질 기준 분포, 임계값, 판정 기준 | 관계형 테이블 조회 (`lookup/`) | 실구현 있음 |
| MES, 이미지 메타데이터 | 조인과 집계 | `manifest.csv` 4,039행 |
| 과거 이슈 이력 | 그래프 검색. 역할은 **중복 차단 하나** | 24건 |

**실측 방식 비중이 조인 8 · 그래프 2 · 집계 1** 입니다(실모델 전 구간 실행). "전부 RAG 로 찾습니다"가 아니고, 이 구분 자체가 제안의 논거입니다.

접수 입력을 메일로 만드는 방법은
[`examples/가상메일_작성가이드.md`](examples/가상메일_작성가이드.md) 에 있습니다.

### 터미널 없이 확인하는 법

`data/scenarios.yaml` 을 **GitHub 웹에서 고쳐 커밋하면 형식 검사가 자동으로
돌아갑니다.** 1~2분 뒤 커밋 옆에 ✅ 또는 ❌ 가 뜨고, ❌ 를 누르면 무엇이
잘못됐는지 한국어로 나옵니다. 그 메시지를 웹 클로드에 붙여넣어 고쳐 달라고
하시면 됩니다.

파이썬을 쓰실 수 있으면 같은 검사를 직접 돌려도 됩니다.

```bash
python scripts/check_scenarios.py     # 시나리오 형식
python scripts/demo_diagnose.py       # 이슈 접수부터 진단까지 (데이터 없이도 됨)
python -m pytest tests/ -q            # 전체 테스트
```

## 개발 환경 준비

```bash
git clone https://github.com/LEEGILJUN/SK_AI_Hackathon.git
cd SK_AI_Hackathon
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# VisA 데이터셋을 내려받아 가상 공장 폴더트리를 생성한다
python data/build_factory.py
```

**GPU 를 쓰려면 한 단계가 더 있습니다.** 위 명령만으로는 torch 가 CPU 판으로
깔립니다(Windows 기준). `requirements.txt` 맨 위의 설치 순서를 보세요.
확인은 이 한 줄입니다 — `2.13.0+cu126 True` 가 나와야 합니다.

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

환경별 파이썬 경로(conda·Windows)는 [`docs/이어서작업.md`](docs/이어서작업.md)
1장 표에 있습니다.

`data/build_factory.py`는 시드를 고정해 동작하므로, 각자 실행하면 동일한 구조가 만들어집니다. **VisA 원본 이미지와 메모리 뱅크 파일은 저장소에 포함되지 않습니다.**

| coreset 증폭 | 끌어올리는 것은 **결함이 있는 이미지**이지 결함이 아님 |
| 역추적 | 뱅크 오염이 **실제로 해를 끼쳤을 때** 짚음 (12/12 대 0/12) |
| 자리별 기준선 빼기 | **위치 추정에는 안 됨** — 상위 5자리에서도 5/10 |
| 고립도 | 정밀도 100% · 재현율 10%. 카테고리와 전처리를 탐 |
| 임계값 스윕 | **"푼 줄 알게" 만듦** — 지표는 통과인데 운영 임계값에서 0/12 |

---

## 안 하기로 한 것

**다시 집어 들지 마세요.** 지우기만 하면 다음 사람이 또 합니다.

| 무엇 | 왜 |
|---|---|
| 네트워크 차단 완주 검증 | 값에 비해 비쌈 |
| 판별 5번 모델 재선정 | `gemma4-12b-vision` 으로 정해짐 |
| 패치 단위 고립도 | 결과가 어느 쪽이든 행동이 안 바뀜 |
| 768/672 해상도 | 512 가 모자란 카테고리가 없음 |
| SAM3 를 VLM 으로 | 분할 전용이라 판단을 대체 못 하고 Python 3.12 요구 |
| 타일 앙상블 | coreset 이 O(k·N) 이라 10.4배 느려짐(실측) |
| `prepare_release` 자동 호출 | 프롬프트로 됨. 자동 호출은 "모델이 순서를 정한다"를 마지막에서만 깨뜨림 |

## 막히면 우선순위

범위를 넓히고 싶어지면 멈추고 이걸 봅니다.

1. **하나가 끝까지 도는 것이 여러 개가 반쯤 되는 것보다 낫다.** 압력이 생기면 **뱅크 오염 시나리오 한 건의 완결된 루프**를 우선한다.
2. **뱅크 오염과 정상 분포 중첩은 반드시 함께 구현하고 시연한다.** 둘의 구분이 진단의 핵심이다.
3. 여섯 원인 중 넷은 뱅크 재구성이 답이 아니다. **하지 말아야 할 때 멈추는가**가 진짜 평가 지점이다.

## 저장소 규칙

- 대용량 바이너리(VisA 원본, `.pt`/`.npz` 뱅크, 실행 로그)는 커밋하지 않습니다. 스크립트로 재현합니다.
- `data/scenarios.yaml`은 **정답 파일**입니다. 진단 정확도를 맞추기 위해 수정하지 않습니다. 변경이 필요하면 합의 후 진행합니다.
- 대회 기간 중에는 저장소를 비공개로 유지합니다.

자세한 내용은 [`docs/작업목록.md`](docs/작업목록.md) 7장을 참고하세요.

## 데이터 출처 및 라이선스
