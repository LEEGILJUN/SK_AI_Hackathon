# 검사 AI 자율 운영 에이전트

**못 잡는 불량을 스스로 학습해 배포까지 준비하는 Self-Healing Vision Ops**

2026 SK AI 해커톤 · AI Solution 리그

---

## 이게 무엇인가

제조 현장에 배포된 AI 외관검사 모델이 "못 잡는 불량"을 만났을 때, 원인 진단부터 데이터 선별, 뱅크 재구성, 성능 검증, 배포 패키지 생성까지를 에이전트가 스스로 수행합니다.

검사 모델을 새로 만드는 프로젝트가 아니라, **이미 배포된 모델을 계속 살아 있게 유지하는 운영의 문제**를 다룹니다.

기준 모델은 PatchCore입니다. 정상 패치를 메모리 뱅크에 담아두고 최근접 거리로 판정하는 구조라, 미검출이 발생했을 때 그 이미지가 어떤 정상 패치와 가까웠는지를 되짚을 수 있습니다. 진단 에이전트는 이 경로를 따라가 원인을 규명합니다.

`data/scenarios.yaml` 을 **GitHub 웹에서 고쳐 커밋하면 형식 검사가 자동으로
돌아갑니다.** 1~2분 뒤 커밋 옆에 ✅ 또는 ❌ 가 뜨고, ❌ 를 누르면 무엇이
잘못됐는지 한국어로 나옵니다. 그 메시지를 웹 클로드에 붙여넣어 고쳐 달라고
하시면 됩니다.

파이썬을 쓰실 수 있으면 같은 검사를 직접 돌려도 됩니다.


```bash

cd SK_AI_Hackathon
```

## 이길준 — LLM · 에이전트 · 추론

### 1주 차

- [ ] **6. LLM·VLM 실행 환경 구축** → 에이전트 실행 기반
  - 어댑터 인터페이스부터 고정한다. `chat(messages, tools)`와 `see(image, prompt)` 두 개만 노출하고 뒤에 로컬 모델과 API를 각각 붙인다.
  - `openai` 클라이언트로 vLLM·Ollama의 OpenAI 호환 엔드포인트를 때리면 폐쇄망 경로와 API 경로가 같은 코드로 돈다. 모델 교체는 설정값 하나로.
  - 합격선: **네트워크를 끊은 상태에서 도구 호출이 한 번 성공**해야 한다.

- [ ] **7. PatchCore 추론 파이프라인 + 뱅크 역추적** → 이상 점수, 최근접 패치 추적
  - 뱅크를 만들 때 `patch_id → (원본 이미지 경로, 패치 좌표)` 매핑 테이블을 **반드시 함께 저장**한다. 이게 없으면 역추적이 안 되고 진단 전체가 성립하지 않는다.
  - 출력은 이상 점수 하나가 아니라 "몇 번 패치와 얼마나 가까웠는지"까지다.
  - 이 과제에서 가장 먼저 돌아가야 하는 작업. 여기가 막히면 13번을 못 짠다.

- [ ] **11. 이슈 접수 인터페이스 + 인테이크 에이전트** → 자연어 이슈 구조화
  - 라인·영역·결함 유형·기간을 뽑아내고, 부족하면 되묻는다. FastAPI + 이미지 첨부.
  - 판단하는 것은 두 가지다. 정보가 충분한가, 이미 해결된 사례인가.

- [ ] **12. 임계값 스윕 — 검출률·과검률 곡선** → 임계값 한계 정량화
  - 임계값을 낮춰가며 검출률과 과검률의 관계를 곡선으로 낸다.
  - 정상 분포 중첩 케이스에서 **"이 결함을 잡으려면 과검률이 얼마가 된다"**를 숫자로 보여주는 근거가 된다. 임계값으로는 해결 안 됨을 증명하는 도구다.

- [ ] **5. 판별 항목 조회 스키마 정의** *(이동현과 공동)* → 테이블 스키마, 조회 함수 명세
  - 판별 항목 2·3·4·6·7번이 각각 어떤 테이블을 때리는지 **함수 시그니처로 먼저 적는다.**
  - 여기서 정한 함수 목록이 곧 에이전트의 도구 목록이 된다.

- [ ] **13. 진단 에이전트 구현** *(장영진과 공동)* → 원인 6종 분류 + 근거 리포트
  - 판별 항목 7가지를 조합해 6원인 중 하나로 떨어뜨린다. **근거 없는 판정은 실패로 친다.**
  - 핵심은 4번(최근접 패치가 무엇인가)과 5번(그게 결함인가 진짜 정상품인가)이 갈리는 지점. 결함이면 뱅크 오염, 진짜 정상품이면 정상 분포 중첩. 조치가 정반대다.
  - 순차 스크립트로 짜지 않는다. 판단하고 다음으로 넘길지를 결정하는 구조여야 한다.

  - 이슈 접수부터 승인까지를 사람 기준 절차 문서로. 시스템 흐름이 아니라 누가 무엇을 언제 판단하는지.

- [ ] **22. 거버넌스 기록 스키마** *(이동현과 공동)* → 재학습 의도 기록 구조
  - 무엇을 남겨야 조직 자산이 되는가. 재학습 의도, 판단 근거, 승인자, 시각.
  - 사후에 "왜 이 시점에 뱅크를 바꿨나"에 답할 수 있어야 한다.

- [ ] **17. 평가 게이트 자동 판정** *(이길준과 공동)*
  - 무엇을 통과로 볼지는 도메인 판단이다. 기준값을 장영진이 정한다.

## 이동현 — 데이터 · 가상공장

### 1주 차

- [ ] **1. VisA 확보 및 가상 공장 폴더트리 구성** → 라인별 스토리지, 일자별 생산 데이터
  - VisA에서 **성격이 다른 3~4개 객체**를 골라 각각 별개 라인으로 둔다.
  - 일자별로 쪼갠다. 1~4일분은 초기 뱅크 구성용, 5~7일분은 운영 데이터용.
  - 전부 `data/build_factory.py` 하나로 끝낸다. **시드 고정이 필수다.** 세 명이 각자 돌려 같은 트리가 나와야 재현성 목표가 성립한다.
  - 원본 이미지는 커밋하지 않는다. 스크립트가 내려받아 배치하는 구조.

- [ ] **4. 가상 MES 데이터 생성** → 로트·설비·조건·시각 테이블
  - `data/mes.csv`에 로트, 설비 ID, 공정 조건, 시각, 검사 결과. `data/manifest.csv`가 이미지 ↔ 라인/일자/로트를 잇는다.
  - **조인 키를 먼저 정하고 만든다.** 진단 에이전트가 "이 로트의 이미지 전부"를 뽑아야 하므로 manifest와 mes가 로트로 붙어야 한다.
  - 벡터화하지 않는다. 조인과 집계로 정확히 답할 문제다.
  - 실제 공정 조건이나 장비 공급사명은 넣지 않는다. 전부 가상값.

- [ ] **10. 학습 이력 인덱서** → 폴더 스캔 → 뱅크 프로파일 복원
  - 어떤 이미지가 어느 뱅크 버전에 들어갔는지를 폴더 스캔만으로 복원한다. 버전 간 차이 비교까지.
  - **사내 폴더 구조를 전제하지 않는다.** 일반적인 스캔 규칙으로 추상화한다.
  - 복원한 이력은 **추정으로 표시**하고 근거를 남긴다. 담당자 확인 후에만 확정으로 승격.

- [ ] **8. 화질 지표 기준 분포 산출** *(장영진과 공동)*
  - 지표 정의와 이탈 규칙은 장영진이 정하고, 값 산출은 이동현이 한다.
  - **기준 분포는 반드시 초기 뱅크 구간(1~4일분)에서만 뽑는다.** 열화를 주입한 5~7일분이 섞이면 기준 자체가 오염돼 설비 문제를 영영 못 잡는다.

- [ ] **5. 판별 항목 조회 스키마 정의** *(이길준과 공동)*
  - 뱅크 구성 프로파일, 화질 기준 분포, 임계값, 판정 기준을 관계형 테이블 + 조회 함수로. 저장소는 표준 라이브러리 `sqlite3`면 충분하다.

### 2주 차

- [ ] **26. 과거 이슈 이력 생성 및 그래프 구축** → 이슈 → 원인 → 조치 연결
  - 시나리오의 중복 케이스가 여기서 걸려야 하므로, **동일 케이스를 사전에 배치**해 둔다.

- [ ] **14. 그래프 검색 — 유사 사례 탐색** → 중복 이슈 차단

## 막히면 우선순위

범위를 넓히고 싶어지면 멈추고 이걸 봅니다.

1. **하나가 끝까지 도는 것이 여러 개가 반쯤 되는 것보다 낫다.** 압력이 생기면 **뱅크 오염 시나리오 한 건의 완결된 루프**를 우선한다.
2. **뱅크 오염과 정상 분포 중첩은 반드시 함께 구현하고 시연한다.** 둘의 구분이 진단의 핵심이다.
3. 여섯 원인 중 넷은 뱅크 재구성이 답이 아니다. **하지 말아야 할 때 멈추는가**가 진짜 평가 지점이다.

## 저장소 규칙

- 대용량 바이너리(VisA 원본, `.pt`/`.npz` 뱅크, 실행 로그)는 커밋하지 않습니다. 스크립트로 재현합니다.
- `data/scenarios.yaml`은 **정답 파일**입니다. 진단 정확도를 맞추기 위해 수정하지 않습니다. 변경이 필요하면 합의 후 진행합니다.
- 대회 기간 중에는 저장소를 비공개로 유지합니다.

자세한 내용은 [`docs/작업목록.md`](docs/작업목록.md) 7장을 참고하세요.
